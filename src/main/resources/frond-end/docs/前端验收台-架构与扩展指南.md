## 1. 项目定位与边界

这不是一个业务前端，而是一个**接口验收台 / 联调控制台**：

- 不做登录、路由、权限、骨架屏、组件库，只有一个页面壳。
- 所有能力都围绕「发一个真实 HTTP 请求 → 展示原始响应 → 对照后端契约判断是否符合预期」。
- 相对后端而言是**旁路工具**：后端接口不存在时前端不会崩，只是请求结果返回 404/业务码。

三个工作区各自承担一类验收：

| 工作区 | 文件 | 用途 |
| --- | --- | --- |
| 商品验收 | `src/views/ProductView.vue` | 用真实表单走「新增 → 详情」闭环，观察字段校验、脱敏、状态文案 |
| 接口调试 | `src/views/DebugView.vue` | 通用 HTTP 客户端；侧边栏登记的接口会自动载入这里 |
| 异常演练 | `src/views/ErrorLabView.vue` | 批量执行异常场景，自动比对 HTTP 状态码与业务码，给出通过/失败 |

**明确不做的事**：不发生产请求、不接真实用户、不做前端业务逻辑。所以「页面不好看」「没有路由」都不是缺陷，除非它妨碍验收。

## 2. 技术栈与运行链路

| 项 | 值 |
| --- | --- |
| 框架 | Vue 3（`<script setup>` 组合式 API） |
| 构建 | Vite 6 |
| 状态 | Vue `reactive` 单例，无 Pinia、无 Vuex |
| 路由 | 无 `vue-router`，用 `workspace.view` 字段切换组件 |
| 请求 | 原生 `fetch`，无 axios |
| 样式 | 单个全局 `src/styles.css` + 各组件 `<style scoped>`，无 UI 库 |
| Node | Vite 6 要求 Node 18+（建议 20+） |

### 2.1 开发时代理

```text
浏览器 (http://localhost:5173)
   │  fetch('/api/product/1')、fetch('/actuator/health')
   ▼
Vite dev server（同源）
   │  proxy
   ▼
Spring Boot（http://localhost:8089，application.yml 中 server.port）
```

`vite.config.js` 只代理了两个前缀：

```js
'/api'      → target
'/actuator' → target
```

这样浏览器看到的始终是同源请求，**后端不需要配置 CORS**。反过来，如果以后接口前缀不再是 `/api`（例如网关改成 `/mall/api`），必须同步新增代理规则，否则请求会落到 Vite 自己身上返回 404。

### 2.2 目标地址

默认 `http://localhost:8089`，两种改法：

```bash
# 当前 shell 临时指定（Git Bash / macOS / Linux）
VITE_API_TARGET=http://192.168.1.20:8089 npm run dev

# Windows CMD
set VITE_API_TARGET=http://192.168.1.20:8089 && npm run dev
```

或直接改 `vite.config.js` 里的默认值。

> 注意：`vite.config.js` 用的是 `process.env.VITE_API_TARGET`，**只读取 shell 环境变量**，不会自动读 `.env` 文件。若想支持 `.env`，需要改用 Vite 的 `loadEnv()`。

### 2.3 构建与托管

```bash
npm run build     # 产物 dist/
npm run preview   # 4173 端口，代理同样生效
```

若想让 Spring Boot 直接托管：把 `dist/` 内容拷到 `src/main/resources/static/`，访问 `http://localhost:8089/`。此时是同源，不经过 Vite 代理。

当前 `pom.xml` 已排除 `frond-end/**`，前端源码和 `node_modules` 不会被打进 jar：

```xml
<resource>
  <directory>src/main/resources</directory>
  <excludes>
    <exclude>frond-end/**</exclude>
  </excludes>
</resource>
```

## 4. 整体数据流

```text
┌─ App.vue ──────────────────────────────────────────────┐
│  views[] ──workspace.view──▶ <component :is="...">     │
│  endpointGroups[] ──点击──▶ loadEndpoint(endpoint)     │
│  健康检查 ──fetch /actuator/health──▶ health state     │
└────────────────────────────────────────────────────────┘
        │ 切换
        ▼
┌─ DebugView ────────────────────────────────────────────┐
│  workspace.draft { method, path, pathParams, query,    │
│                    body, sourceId }                    │
│         │ 发送                                         │
│         ▼                                              │
│  sendRequest()  ──▶  fetch('/api/...')                 │
│         │                                              │
│         ▼                                              │
│  统一结果对象  ──▶  <ResponsePanel :result="...">      │
└────────────────────────────────────────────────────────┘

ProductView  / ErrorLabView 不依赖 endpoints.js，

```

关键点：**所有请求都经过 `sendRequest`，所有响应都用同一个结果形状，所有展示都走 `ResponsePanel`**。扩展时保持这三条不破，页面行为就一致。

## 5. 核心模块详解

### 5.1 `src/api/http.js` — 统一请求封装

唯一导出 `sendRequest(options)`。

#### 入参

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `method` | string | `'GET'` | 内部转大写 |
| `path` | string | `''` | 必填；可以是相对路径 `/api/...` |
| `pathParams` | object | `{}` | 替换路径里的 `{name}` 占位符 |
| `query` | array | `[]` | `[{ key, value }]`，`key` 为空的行被忽略 |
| `body` | object / string / null | `null` | 非 GET/HEAD 才会实际发送 |

#### URL 拼装顺序

1. `path` 去首尾空格；为空直接 `throw new Error('请填写请求路径')`。
2. 遍历 `pathParams`，把 `{key}` 替换为 `encodeURIComponent(value ?? '')`（未填则替换为空串）。
3. 遍历 `query`，跳过空 `key`，用 `URLSearchParams` 拼接；已有 `?` 时用 `&`。

#### Body 规则

- 只有 `GET` / `HEAD` 之外的请求才允许带 body。
- body 为 `null` / `undefined` / 空串时不发送，也不会设置 `Content-Type`。
- 发送时：对象自动 `JSON.stringify`，字符串原样发送，并设置 `Content-Type: application/json`。
- 始终设置 `Accept: application/json`。

> 这也意味着：**文件上传（multipart/form-data）目前不支持**，见 [8.5](#85-文件上传或非-json-请求)。

#### 返回结果形状

无论 HTTP 状态如何（甚至网络失败），都返回同一结构，便于 `ResponsePanel` 统一渲染：

```js
{
  request: { method, url, body },  // 实际发出的请求
  httpStatus,                      // number | null（网络失败为 null）
  httpStatusText,
  httpOk,                          // response.ok
  elapsedMs,                       // 毫秒，performance.now() 计时
  headers,                         // 响应头对象
  rawText,                         // 原始响应文本（始终保留）
  json,                            // 能 JSON.parse 时的对象，否则 null
  networkError,                    // 网络层错误信息，成功时为 null
  success,                         // 见下
  at                               // ISO 时间字符串
}
```

#### `success` 的判定（重要）

```js
success =
  json !== null && typeof json === 'object' && 'code' in json
    ? json.code === 0      // 业务码为准
    : response.ok          // 非 Result 结构（如 /actuator/health）回退到 HTTP
```

**判断本次请求是否成功，永远看 `code === 0`，不要看 HTTP 状态码。** 本项目的后端在 404 路由和 500 系统异常时都返回 HTTP 200（见第 7 节）。

#### 网络错误

`fetch` 抛异常时不向上抛，而是返回 `httpStatus: null`、`networkError: '...'`、`success: false` 的结果对象。因此调用方不需要 try/catch，但仍可以查看 `networkError` 区分「后端没起来」和「后端返回了错误」。

### 5.2 `src/api/endpoints.js` — 接口清单

这是一个**纯配置数组**，按分组组织：

```js
export const endpointGroups = [
  {
    name: '商品',
    endpoints: [
      {
        id: 'product-create',       // 唯一标识，用于高亮当前载入项
        name: '新增商品',            // 侧边栏显示名
        method: 'POST',
        path: '/api/product',
        summary: '创建商品并返回落库结果；status 由服务端固定为 1（上架）。',
        pathParams: {},             // 可选
        query: [],                  // 可选
        body: { name: '手冲咖啡壶', price: 129.0, /* ... */ }, // 可选
      },
    ],
  },
]
```

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `id` | 是 | 唯一标识；`workspace.draft.sourceId` 与它比对决定高亮 |
| `name` | 是 | 侧边栏按钮文字 |
| `method` | 是 | GET/POST/PUT/PATCH/DELETE |
| `path` | 是 | 可含 `{id}` 占位符 |
| `summary` | 否 | 载入调试台后显示在请求区上方 |
| `pathParams` | 否 | 占位符默认值，如 `{ id: '1' }` |
| `query` | 否 | `[{ key: 'pageNum', value: '1' }]` |
| `body` | 否 | 对象，载入时格式化为 2 空格缩进 JSON 文本 |

另有工具导出：

```js
export const allEndpoints = endpointGroups.flatMap(group => group.endpoints)
```

`DebugView` 用它根据 `sourceId` 反查当前接口的 `summary`。

**这个文件只描述「接口」，不负责发请求**。新增接口 90% 的情况只改这里。

### 5.3 `src/stores/workspace.js` — 工作区状态

模块级 `reactive` 单例，所有组件共享同一份状态。**没有持久化，刷新页面即重置。**

```js
workspace = {
  view: 'product',       // 'product' | 'debug' | 'lab'
  draft: {
    sourceId: null,      // 来自哪个接口配置，null 表示手填
    method: 'GET',
    path: '/api/lab/hello',
    pathParams: {},      // 键为占位符名
    query: [ { id: 'q1', key: '', value: '' } ],
    body: '',            // JSON 文本
  },
}
```

导出函数：

| 函数 | 作用 |
| --- | --- |
| `makeQueryRow(key, value)` | 生成带自增 `id` 的 query 行（用于 `v-for :key`，避免删除时复用错行） |
| `switchView(view)` | 切换工作区 |
| `loadEndpoint(endpoint)` | 用接口配置覆盖 `draft`，并自动切到 `debug` 工作区 |
| `resetDraft()` | 恢复默认草稿（GET `/api/lab/hello`） |

`loadEndpoint` 的细节：

- `pathParams` 做浅拷贝，避免直接改动 `endpoints.js` 里的原对象。
- `query` 为空时自动补一行空行，保证 UI 至少有一个输入框。
- `body` 为对象时 `JSON.stringify(endpoint.body, null, 2)`；为 `undefined` 时置空字符串。

由于没有路由，**「当前在哪个工作区」也是内存状态**，刷新后回到商品验收。

### 5.4 `src/components/ResponsePanel.vue` — 响应面板

三个工作区共用。

**Props**

| Prop | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `result` | Object | `null` | `sendRequest` 的返回值；为空显示 `emptyHint` |
| `emptyHint` | String | `'尚未发送请求'` | 空态文案 |
| `compact` | Boolean | `false` | 紧凑模式（异常演练卡片里用），响应体默认折叠 |

**展示内容**

1. 状态印章：网络错误 → `连接失败`；否则 `success ? 成功 : 失败`（tone 为 pass/fail）。
2. `METHOD url`、`HTTP xxx`、耗时 `xx ms`、业务码 `code xxx`。
3. 网络错误文本，或后端返回的 `json.message`。
4. 「格式化 / 原始」两个 Tab：格式化显示 `JSON.stringify(json, null, 2)`；原始显示 `rawText`（非 JSON 响应会落到这里）。
5. 复制按钮（复制 `rawText`）与响应时间。
6. `compact` 模式下额外有「展开响应 / 收起响应」开关。

**注意**：`businessCode` 只有在 JSON 是对象且含 `code` 字段时才显示；`/actuator/health` 这类响应会显示 `—`。

- `views` 数组定义三个工作区（key、label、标题、说明、组件）。

## 6. 三个工作区

### 6.1 商品验收 `ProductView.vue`

两栏布局：左「新增商品」，右「商品详情」。

**新增表单**

| 字段 | 控件 | 规则提示 | 发送值处理 |
| --- | --- | --- | --- |
| 商品名称 | text | 2–20 字 | 原样字符串 |
| 价格 | text + decimal | ≥ 0.01，2 位小数 | 空串 → `null`；否则 `Number()`，非有限数 → `null` |
| 库存 | text + numeric | ≥ 0 | 空串 → `null`；否则 `Number()` |
| 联系电话 | text + tel | 11 位手机号，可不填 | trim 后空 → `null` |
| 描述 | textarea | ≤ 100 字 | trim 后空 → `null` |

两个演示按钮：

- **填入合法示例**：符合后端 `ProductCreateDTO` 全部约束的样例。
- **填入非法示例**：`name='A'`、`price=0`、`stock=-1`、`contactPhone='12345678901x'`、`description` 101 个字。预期 HTTP 400 + 业务码 40000，用于观察校验消息如何按字段拼接。

**提交流程**

```text
submitCreate()
  → POST /api/product（body 为 toPayload()）
  → createResult 交给左侧 ResponsePanel
  → 若 success 且 json.data.id 存在：
      记录 createdProduct，自动把 id 填入右侧详情输入框
```

新增成功后出现「已创建」条带，可点击「查看详情」直接触发 `loadDetail()`。

**详情展示**

查询 ID 来自自动回填或手动输入（回车也可查询）。`detailProduct` 只在 `result.success` 时取 `json.data`。

| 展示项 | 来源 | 说明 |
| --- | --- | --- |
| 状态印章 | `status` / `statusText` | `status === 1` 为 pass，否则 warn；文案优先用后端 `statusText` |
| 价格 | `price` | 前端格式化为 `¥ 129.00` |
| 库存 | `stock` | 空显示 `—` |
| 联系电话 | `contactPhone` | 后端已脱敏（`138****8000`） |
| 库存预警 | `stockWarning` | `null` 显示「接口未返回」，`true` 显示「低于阈值」，`false` 显示「正常」 |
| 创建 / 更新时间 | `createTime` / `updateTime` | 原样显示 |
| 描述 | `description` | 空显示 `—` |

> 当前后端 `ProductServiceImpl.toVO()` **没有给 `stockWarning` 赋值**，因此页面会稳定显示「接口未返回」。这属于后端待补字段，不是前端 bug；等后端补上后，前端无需改动即可显示。

**后端 `ProductVO` 变更时改这里**：新增字段 → 在 `record-grid` 里加一个 `<div><dt>…</dt><dd>…</dd></div>`；若字段需要特殊格式化，加一个 computed 或格式化函数。

### 6.2 接口调试 `DebugView.vue`

左侧请求面板，右侧响应面板。

**请求区**

1. **Method + Path**：method 下拉（GET/POST/PUT/PATCH/DELETE），path 自由输入，示例 `/api/product/{id}`。
2. **路径参数**：用正则 `/\{([^{}]+)\}/g` 从 path 中提取占位符名（去重）。`watch` 到新占位符时自动在 `draft.pathParams` 中补空串；**删除占位符时不会删除对应键**——残留键无害，因为替换只针对 URL 中实际出现的 `{name}`。
3. **Query 参数**：可增删行。删除到 0 行会自动补一行。`key` 为空的行在发送时被忽略。
4. **JSON Body**：
   - 仅非 GET/HEAD 方法显示「该请求不会发送 body」的提示（文本仍保留）。
   - 实时校验：非空且 `JSON.parse` 失败时显示错误，并**禁用发送按钮**。
   - 「格式化」按钮会重新缩进为 2 空格。
5. **发送**：按钮或 `Ctrl/Cmd + Enter`。发送期间按钮禁用，防重复提交。
6. **清空**：`resetDraft()` + 清空结果。

**载入接口**：从侧边栏点击后，`sourceId` 设置并自动切到本工作区；顶部显示该接口的 `summary`；method/path/pathParams/query/body 全部来自 `endpoints.js`。

**适用边界**：单请求、JSON 即可表达的接口都能在这里测。需要多步骤串联、结果断言、列表渲染时，再考虑新增专用视图。

---

### 6.3 异常演练 `ErrorLabView.vue`

内置 5 个场景，每个场景是一个配置对象：

```js
{
  id: 'validation',
  title: '参数校验失败',
  method: 'POST',
  path: '/api/product',
  body: { /* ... */ },       // 可选
  expectedHttp: 400,         // 预期 HTTP 状态码
  expectedCode: 40000,       // 预期业务码
  note: '触发 @Valid + MethodArgumentNotValidException……',
}
```

当前场景与预期：

| 场景 | 请求 | 预期 HTTP | 预期业务码 | 触发点 |
| --- | --- | --- | --- | --- |
| 参数校验失败 | `POST /api/product`（非法 body） | 400 | 40000 | `MethodArgumentNotValidException` |
| 商品不存在 | `GET /api/product/999999` | 400 | 10001 | `PRODUCT_NOT_FOUND` |
| 业务异常 | `GET /api/lab/businessException` | 400 | 10001 | `BusinessException` |
| 接口不存在 | `GET /api/no-such-endpoint` | 200 | 40400 | `NoResourceFoundException`（无 `@ResponseStatus`） |
| 系统异常 | `GET /api/lab/exception` | 200 | 50000 | `Exception` 兜底 |

**判定逻辑**：

```js
const codeOk = result.json?.code === scenario.expectedCode
const httpOk = result.httpStatus === scenario.expectedHttp
pass = codeOk && httpOk          // 两者必须同时满足
```

- 全部执行是**串行**的（避免并发请求干扰数据库/日志观察）。
- 每个场景卡片显示「通过 / 不符预期」印章；不通过时额外显示实际业务码或实际 HTTP。
- 顶部显示 `通过数 / 已执行数`。

**添加场景 = 往 `scenarios` 数组追加一项**，无需改模板。详见 [8.3](#83-方式三给异常演练加场景)。

## 7. 后端契约速查（前端依赖的部分）

### 7.1 统一响应 `Result<T>`

```json
{
  "code": 0,
  "message": "成功",
  "data": { },
  "timestamp": "2026-11-11T16:00:00"
}
```

前端只看 `code`、`message`、`data`；`timestamp` 仅在格式化面板里可见。

### 7.2 业务码

| code | 含义 | 典型 HTTP |
| --- | --- | --- |
| `0` | 成功 | 200 |
| `40000` | 请求参数错误 | 400 |
| `40100` | 未登录 / 登录过期 | 尚未使用 |
| `40300` | 没有权限 | 尚未使用 |
| `40400` | 资源/接口不存在 | **200**（见下） |
| `40900` | 数据冲突 | 尚未使用 |
| `50000` | 系统内部错误 | **200**（见下） |
| `10001` | 商品不存在 | 400 |
| `10002` | 商品库存不足 | 尚未使用 |
| `10003` | 商品已下架 | 尚未使用 |

### 7.3 两个必须记住的后端行为

1. **路由 404**：`GlobalExceptionHandler.handleNotFoundException` 没有 `@ResponseStatus`，所以 HTTP 状态是 **200**，业务码 `40400`。
2. **系统异常 500**：兜底 `Exception` 处理器同样没有 `@ResponseStatus`，HTTP **200**，业务码 `50000`。

因此：

- 前端判定成功一律用 `success`（即 `code === 0`），不要用 `response.ok`。
- 异常演练里这两个场景的 `expectedHttp` 必须写 `200`，写 500/404 会一直不通过。

### 7.4 当前已有接口

| Method | Path | 说明 | 成功时 `data` |
| --- | --- | --- | --- |
| POST | `/api/product` | 新增商品 | `ProductVO` |
| GET | `/api/product/{id}` | 商品详情 | `ProductVO` |
| GET | `/api/lab/hello` | 连通性示例 | `"ok"` |
| GET | `/api/lab/businessException` | 抛业务异常 | 无 |
| GET | `/api/lab/exception` | 抛运行时异常 | 无 |

> 后端已有 `ProductQueryDTO`、`ProductUpdateDTO`、`PageResult`、`ProductService` 接口，但 Controller 目前只暴露了新增和详情。等分页/更新接口落地后按第 8 节接入。

### 7.5 `ProductVO` 字段

`id, name, price, stock, status, statusText, contactPhone, description, stockWarning, createTime, updateTime`

- `contactPhone` 由后端脱敏（11 位时中间 4 位替换为 `****`）。
- `statusText` 由后端根据 `status` 生成（1 = 上架，其他 = 下架）。
- `stockWarning` 目前后端未赋值（前端显示「接口未返回」）。
- `version`、`deleted` 不返回给前端。

### 7.6 健康检查

`GET /actuator/health`（application.yml 中暴露了 `health,info,metrics`，且 `show-details: always`）。前端只要求 `status === 'UP'`。

## 8. 增量扩展手册

### 8.1 方式一：只登记接口（最常用，90% 的场景）

**适用**：普通 CRUD、查询、动作类接口，用 JSON 收发即可。

**步骤**：

1. 打开 `src/api/endpoints.js`。
2. 在合适的 `group.endpoints` 里追加一项（或新建分组）。
3. 保存，Vite HMR 自动刷新，左侧清单立即出现。
4. 点击该接口 → 自动跳到「接口调试」并载入 method/path/参数/body。
5. 点「发送请求」，用右侧面板核对 HTTP 状态、业务码、`data`。

**模板**：

```js
// 按 ID 更新商品（PUT + 路径参数 + body）
{
  id: 'product-update',
  name: '更新商品',
  method: 'PUT',
  path: '/api/product/{id}',
  summary: '按 ID 更新商品，name/price 为必填。',
  pathParams: { id: '1' },
  body: {
    name: '手冲咖啡壶',
    price: 139.0,
    contactPhone: '13800138000',
    description: '容量 600ml',
  },
},
```

```js
// 分页查询（GET + query）
// 注意：下面只是配置模板，后端分页接口落地后，把 path 换成真实路径。
{
  id: 'product-page',
  name: '商品分页',
  method: 'GET',
  path: '/api/product/page',   // ← 以后端实际路径为准
  summary: '分页查询；pageSize 上限 100。',
  query: [
    { key: 'pageNum', value: '1' },
    { key: 'pageSize', value: '10' },
    { key: 'keyword', value: '' },
  ],
},
```

```js
// 删除（DELETE 无 body）
{
  id: 'product-delete',
  name: '删除商品',
  method: 'DELETE',
  path: '/api/product/{id}',
  summary: '逻辑删除商品。',
  pathParams: { id: '1' },
},
```

**注意**：

- `id` 必须全局唯一；重复会导致侧边栏高亮/`summary` 反查错乱。
- `query` 里的空值行会照常发送（`key` 非空时），不想发就删掉该行或留空 `key`。
- `body` 是**对象**，不要写成字符串；字符串也支持，但会原样发送、不会被格式化。
- 载入后修改参数只影响 `workspace.draft`，不会改回 `endpoints.js`；刷新即恢复默认值。

**验收清单**：见 [11](#11-新增接口验收清单)。

### 8.2 方式二：新增专用工作区（需要自定义表单或列表时）

**适用**：多步骤流程、需要把响应渲染成表格/卡片、需要跨请求联动（如「新增后自动查详情」）。

现有 `ProductView` 就是范例。新增一个工作区的最小步骤：

1. 新建 `src/views/OrderView.vue`：

```vue
<script setup>
import { ref } from 'vue'
import { sendRequest } from '../api/http.js'
import ResponsePanel from '../components/ResponsePanel.vue'

const result = ref(null)
const loading = ref(false)

async function submit() {
  loading.value = true
  try {
    result.value = await sendRequest({
      method: 'POST',
      path: '/api/order',
      body: { productId: 1, quantity: 2 },
    })
  } finally {
    loading.value = false
  }
}
</script>

<template>
  <div class="order-layout">
    <section class="panel">
      <header class="panel-head"><h2>下单</h2><span class="hint">POST /api/order</span></header>
      <div class="panel-body">
        <button class="btn primary" type="button" :disabled="loading" @click="submit">
          {{ loading ? '提交中…' : '提交' }}
        </button>
      </div>
    </section>
    <ResponsePanel :result="result" empty-hint="提交后查看响应。" />
  </div>
</template>

<style scoped>
/* .panel / .btn / .panel-head 来自全局 styles.css；
   .order-layout 这类布局类名要自己定义 */
.order-layout {
  display: grid;
  grid-template-columns: minmax(0, 5fr) minmax(0, 6fr);
  gap: 20px;
  align-items: start;
}
@media (max-width: 1100px) {
  .order-layout { grid-template-columns: 1fr; }
}
</style>
```

2. 在 `src/App.vue` 顶部 import，并向 `views` 数组追加：

```js
import OrderView from './views/OrderView.vue'

const views = [
  // ...已有
  {
    key: 'order',
    label: '订单验收',
    title: '订单验收',
    caption: '提交订单并核对库存扣减与响应结构。',
    component: OrderView,
  },
]
```

3. 如需侧边栏也能一键载入该接口的原始请求，再在 `endpoints.js` 登记一份（可选）。

**约定**：

- 继续复用 `sendRequest` 与 `ResponsePanel`，不要另写 `fetch`。
- 表单的「清空值 → `null`」处理和 `ProductView.toPayload()` 保持一致，避免把空字符串发给后端。
- 组件级样式写在 `<style scoped>`；通用控件类（`.btn`、`.panel`、`.field` 等）已在 `styles.css`。

### 8.3 方式三：给异常演练加场景

编辑 `src/views/ErrorLabView.vue` 的 `scenarios` 数组，追加一项：

```js
{
  id: 'product-invalid-id',
  title: '非法路径参数',
  method: 'GET',
  path: '/api/product/abc',        // 例如触发类型转换异常
  expectedHttp: 400,
  expectedCode: 40000,
  note: 'Path 变量类型不匹配时由 Spring MVC 抛出，确认是否被全局处理器归一化。',
```

注意：

- 若某场景后端返回的是 HTTP 200（如 404/500 兜底），就必须写 `200`。
- 场景按数组顺序**串行执行**。
- 新场景不需要改模板；`verdict()` 会自动处理。

常见需要补的场景：类型转换异常（`MethodArgumentTypeMismatchException`）、缺少请求参数、无效 JSON、重复提交唯一键冲突（40900）、未登录（40100）。

### 8.4 分页 / 列表接口怎么测

后端已有 `PageResult<T>`：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "total": 25,
    "pageNum": 1,
    "pageSize": 10,
    "records": [ { "id": 1, "name": "…" } ]
  }
}
```

**轻量方案**：在 `endpoints.js` 登记 GET + query（见 8.1 模板），在「接口调试」里看格式化 JSON 即可。

**需要表格展示时**：按 8.2 新建视图，读取 `result.json.data.records` 渲染 `<table>`，并用 `total/pageNum/pageSize` 做翻页控件。校验要点：

- `pageNum >= 1`，`pageSize` 在 1–100 之间（`ProductQueryDTO` 的约束）。
- 越界参数应返回业务码 40000。
- 空结果时 `records` 是空数组而不是 `null`。

### 8.5 文件上传或非 JSON 请求

当前 `http.js` **只支持 JSON body**。遇到 `multipart/form-data` 或 `application/x-www-form-urlencoded` 时，需要扩展：

```js
// 在 sendRequest 中增加判断
if (body instanceof FormData) {
  init.body = body          // 不要手动设置 Content-Type，浏览器会带 boundary
} else if (内容类型是表单) {
  headers['Content-Type'] = 'application/x-www-form-urlencoded'
  init.body = new URLSearchParams(body).toString()
} else if (hasBody) {
  headers['Content-Type'] = 'application/json'
  init.body = typeof body === 'string' ? body : JSON.stringify(body)
}
```

同时 `hasBody` 预检查、`DebugView` 的 JSON 校验（`bodyError`）都需要放行非 JSON 内容。建议新增一个 `contentType` 选项，而不是硬编码判断，避免影响现有调用。

---

### 8.6 需要鉴权时

目前没有任何请求头注入。若后端加 JWT/Session：

1. 在 `http.js` 的 `headers` 里统一注入，例如 `Authorization: Bearer ${token}`。
2. token 来源建议先用 `localStorage`；验收台无需登录页，可以在 `App.vue` 顶部加一个输入框写入 `localStorage`。
3. 401 的验收可以补进 `ErrorLabView`（预期 HTTP 401 / 业务码 40100）。
4. 若后端改为 Cookie 会话，`fetch` 需要加 `credentials: 'include'`；同时 Vite 代理的 `changeOrigin` 已够用，但跨域场景要另外确认。

---

### 8.7 接口前缀或目标地址变化

- 只改机器/端口：用 `VITE_API_TARGET` 或改 `vite.config.js` 的默认 `target`。
- 新增前缀（如 `/mall/api`）：在 `vite.config.js` 的 `proxy` 里添加对应键；同时更新 `endpoints.js` 中所有 `path`。
- 后端上了网关且路径被重写：代理仍指向网关地址，前端 `path` 写**浏览器可见的路径**。

## 9. 约定与坑

1. **目录名是 `frond-end`（拼写如此）**，不是 `front-end`。改名前要同步 `pom.xml` 的 `<exclude>frond-end/**</exclude>`、README、以及可能存在的部署脚本。
2. **成功判定看 `code === 0`**，不看 HTTP 状态。后端 404/500 兜底都返回 200。
3. **GET/HEAD 永远不发 body**。在调试台里给 GET 填了 JSON 不会发送，切回 POST 后文本还在。
4. **路径参数只增不减**：删掉 path 里的 `{id}` 后，`draft.pathParams.id` 仍保留，但不会出现在 URL 里，无副作用。
5. **Query 空 key 行被忽略**；key 非空、value 为空会发送 `key=`。
6. **响应体只在能 `JSON.parse` 时填充 `json`**；代理错误页、纯文本会落到 `rawText`，用「原始」Tab 查看。
7. **没有路由、没有持久化**：刷新后回到「商品验收」，调试草稿重置。需要保留草稿时，可把 `workspace.draft` 写进 `sessionStorage`，在 `main.js` 挂载前恢复。
8. **`vite.config.js` 不读 `.env`**（用的是 `process.env`），见 2.2。
9. **前端源码不进 jar**（`pom.xml` 已排除）；想用 Spring Boot 托管必须手动 `npm run build` 后拷 `dist/`。
10. **健康检查只认 `status === 'UP'`**；`DOWN`、非 200、网络错误都会显示异常。
11. **修改 `stores/workspace.js` 可能触发整页刷新**（HMR 边界），调试中的草稿会丢，属正常现象。
12. **`node_modules` 已在 `.gitignore`**；不要把 `dist/` 或依赖提交进仓库。

## 10. 排错速查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 右上角显示「无法连接」 | 后端没启动 / 端口不是 8089 | 启动 Spring Boot；或改 `VITE_API_TARGET` |
| 右上角「后端异常 HTTP 404」 | `/actuator` 未暴露 | 检查 `application.yml` 的 `management.endpoints.web.exposure.include` |
| 页面能开，请求返回 HTML/404 | 路径不以 `/api` 开头，Vite 没代理 | 给 `vite.config.js` 加代理前缀；检查 `path` |
| 请求 200 但判定「失败」 | 业务码不是 0 | 看响应 `code`/`message`；`success` 以业务码为准 |
| 异常演练「商品不存在」不通过 | 后端返回 HTTP 与预期不一致 | 对照第 7.3 节；404/500 场景预期 HTTP 是 200 |
| 点侧边栏接口没反应/不高亮 | `id` 重复或视图未切到 debug | 检查 `endpoints.js` 的 `id` 唯一性 |
| 发送按钮灰着 | body JSON 非法 / path 为空 | 修正 JSON（看红字提示）或补 path |
| 响应面板「（空响应体）」 | 后端返回 204/空 body | 正常；看 HTTP 状态与业务码 |
| 修改 `endpoints.js` 不生效 | 浏览器缓存 / HMR 失败 | 刷新页面；确认 dev server 仍在运行 |
| 生产构建后接口 404 | 未配置后端托管或路径前缀不同 | 把 `dist/` 放入 `static/`，或补齐部署层代理 |
| `npm run dev` 报 Node 版本错误 | Node < 18 | 升级 Node（建议 20 LTS） |

## 11. 新增接口验收清单

每接入一个新接口，建议按此清单过一遍：

- [ ] 在 `endpoints.js` 登记（或确认不需要登记）
- [ ] method、path 与 Controller 的 `@RequestMapping` 完全一致（注意是否有 `/api` 前缀）
- [ ] 路径变量用 `{id}` 形式，与 `@PathVariable` 名称一致（当前后端是 `{id}` → `Long id`）
- [ ] Query 参数名与 DTO 字段一致；分页记得 `pageNum`/`pageSize`
- [ ] Body 字段与 DTO 一致；日期/金额用字符串或数字时确认 Jackson 能反序列化
- [ ] 正常路径：`code === 0`，`data` 结构符合预期
- [ ] 校验失败：HTTP 400 + 业务码 40000，`message` 包含字段名
- [ ] 资源不存在：确认是业务码 10001（HTTP 400）还是 40400
- [ ] 系统异常：确认仍是 HTTP 200 + 50000（若不是，同步修正前端判定）
- [ ] 字段展示：新增/变更的 VO 字段已在 `ProductView` 或专用视图里体现
- [ ] 脱敏/派生字段（`statusText`、`contactPhone`、`stockWarning`）与后端实现一致
- [ ] 若接口需要鉴权/特殊 Content-Type，已按 8.5 / 8.6 扩展 `http.js`
- [ ] 更新本文件第 7.4 节与 `README.md` 的接口说明（如有必要）
