# 第 01 章实战：mall-product 商品管理工程化项目

> 配套教程：[01-SpringBoot工程化进阶.md](01-SpringBoot工程化进阶.md)

## 0. 实战地图

### 0.1 你最终要做出的接口

| 方法 | 路径 | 作用 | 练到的知识点 |
|---|---|---|---|
| POST | `/api/products` | 新增商品 | DTO、参数校验、统一返回 |

## 第 0 阶段：建库、建项目、能启动

**本阶段目标**：MySQL 里有表，IDEA 里有项目，运行后 `/actuator/health` 返回 `UP`。

**预计用时**：1 小时。

### 0.1 创建数据库和表

打开终端，登录 MySQL：

```bash
mysql -uroot -p
```

输入密码后，粘贴下面的 SQL。注意：**练习库叫 `mall_product`，和教程里的 `roadmap_db` 分开**，避免后面章节的数据互相干扰。

```sql
-- ============================================================
-- mall-product 练习库
-- ============================================================

CREATE DATABASE IF NOT EXISTS mall_product
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

USE mall_product;

-- 商品表
CREATE TABLE IF NOT EXISTS product (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  name          VARCHAR(64)     NOT NULL                COMMENT '商品名称',
  price         DECIMAL(10, 2)  NOT NULL                COMMENT '价格',
  stock         INT             NOT NULL DEFAULT 0      COMMENT '库存',
  status        TINYINT         NOT NULL DEFAULT 1      COMMENT '状态：1 上架，0 下架',
  contact_phone VARCHAR(20)     DEFAULT NULL            COMMENT '联系人手机号',
  description   VARCHAR(500)    DEFAULT NULL            COMMENT '描述',
  version       INT             NOT NULL DEFAULT 0      COMMENT '乐观锁版本',
  deleted       TINYINT         NOT NULL DEFAULT 0      COMMENT '逻辑删除：0 否，1 是',
  create_time   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_name (name),
  KEY idx_status_price (status, price)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '商品表';

-- 库存流水表：每次扣减库存写一条，用来观察事务是否回滚
CREATE TABLE IF NOT EXISTS product_stock_log (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  product_id    BIGINT UNSIGNED NOT NULL                COMMENT '商品 ID',
  change_amount INT             NOT NULL                COMMENT '变更数量，负数表示扣减',
  before_stock  INT             NOT NULL                COMMENT '变更前库存',
  after_stock   INT             NOT NULL                COMMENT '变更后库存',
  reason        VARCHAR(64)     NOT NULL                COMMENT '变更原因',
  create_time   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_product_id (product_id)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '库存流水';
```

插入三条测试数据：

```sql
INSERT INTO product (name, price, stock, status, contact_phone, description)
VALUES
  ('机械键盘', 399.00, 50, 1, '13800138000', '87 键青轴'),
  ('无线鼠标', 129.00, 200, 1, '13900139000', '2.4G 静音'),
  ('显示器支架', 199.00, 0, 0, NULL, '气压式');
```

验证：

```sql
SELECT id, name, price, stock, status, deleted FROM product;
```

应该看到 3 行，`deleted` 都是 0。

> **为什么 `update_time` 不在数据库层做 `ON UPDATE CURRENT_TIMESTAMP`？**
> 因为本章要用 MyBatis-Plus 的自动填充来练手。两边都写也能跑，但排查问题时容易搞不清是谁改的时间。练习项目里让 Java 代码负责，意图更清楚。

### 0.6 本阶段坑

1. **MySQL 连不上**：先确认 `mysql -uroot -p` 能登录，再确认库名是 `mall_product`，不是 `roadmap_db`。
2. **`Public Key Retrieval is not allowed`**：JDBC URL 少了 `allowPublicKeyRetrieval=true`。
3. **时间差 8 小时**：JDBC URL 的 `serverTimezone=Asia/Shanghai` 不要删。
4. **Lombok 报"找不到 getter"**：IDEA 安装 Lombok 插件，`Settings → Build → Compiler → Annotation Processors` 勾选 `Enable annotation processing`。
5. **端口被占用**：`netstat -ano | findstr :8080` 找到 PID，再 `taskkill /PID <PID> /F`。

## 第 1 阶段：统一返回与全局异常

**本阶段目标**：任何接口都返回同一种 JSON 结构；业务异常和系统异常走不同日志级别；Controller 里不再写 `try-catch`。

**预计用时**：1～1.5 小时。

### 1.1 错误码枚举

新建 `common/api/ResultCode.java`：

```java
package com.example.mall.common.api;

import lombok.Getter;

@Getter
public enum ResultCode {

    SUCCESS(0, "成功"),
    BAD_REQUEST(40000, "请求参数错误"),
    UNAUTHORIZED(40100, "未登录或登录已过期"),
    FORBIDDEN(40300, "没有权限"),
    NOT_FOUND(40400, "资源不存在"),
    CONFLICT(40900, "数据冲突"),
    INTERNAL_ERROR(50000, "系统内部错误"),

    // 业务错误码：1xxxx 表示商品模块
    PRODUCT_NOT_FOUND(10001, "商品不存在"),
    PRODUCT_STOCK_NOT_ENOUGH(10002, "商品库存不足"),
    PRODUCT_OFF_SHELF(10003, "商品已下架");

    private final int code;
    private final String message;

    ResultCode(int code, String message) {
        this.code = code;
        this.message = message;
    }
}
```

> 错误码没有绝对标准。关键是：全局唯一、分段管理、前端能根据 `code` 做判断。HTTP 状态码表达"协议层"结果，业务码表达"业务层"结果。

### 1.2 统一返回体

新建 `common/api/Result.java`：

```java
package com.example.mall.common.api;

import lombok.Data;

import java.time.LocalDateTime;

@Data
public class Result<T> {

    private int code;
    private String message;
    private T data;
    private LocalDateTime timestamp;

    private Result(int code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
        this.timestamp = LocalDateTime.now();
    }

    public static <T> Result<T> success(T data) {
        return new Result<>(ResultCode.SUCCESS.getCode(), ResultCode.SUCCESS.getMessage(), data);
    }

    public static Result<Void> success() {
        return new Result<>(ResultCode.SUCCESS.getCode(), ResultCode.SUCCESS.getMessage(), null);
    }

    public static <T> Result<T> fail(ResultCode resultCode) {
        return fail(resultCode.getCode(), resultCode.getMessage());
    }

    public static <T> Result<T> fail(ResultCode resultCode, String message) {
        return fail(resultCode.getCode(), message);
    }

    public static <T> Result<T> fail(int code, String message) {
        return new Result<>(code, message, null);
    }
}
```

> **和教程代码的一处小改进**：教程里的全局异常处理把业务异常统一转成 `ResultCode.BAD_REQUEST`，业务码会丢失。这里增加了 `fail(int code, String message)`，让 `BusinessException` 携带的 `10001`、`10002` 原样返回，前端才能区分"商品不存在"和"库存不足"。

### 1.3 分页返回体

```java
package com.example.mall.common.api;

import lombok.Data;

import java.util.List;

@Data
public class PageResult<T> {

    private long total;
    private long pageNum;
    private long pageSize;
    private List<T> records;
```

### 1.4 业务异常

新建 `common/exception/BusinessException.java`：

```java
package com.example.mall.common.exception;

import com.example.mall.common.api.ResultCode;
import lombok.Getter;

@Getter
public class BusinessException extends RuntimeException {

    private final int code;

    public BusinessException(ResultCode resultCode) {
        super(resultCode.getMessage());
        this.code = resultCode.getCode();
    }

    public BusinessException(ResultCode resultCode, String message) {
        super(message);
        this.code = resultCode.getCode();
    }
}
```

> **必须继承 `RuntimeException`**。如果继承 `Exception`，默认事务规则不会回滚，后面第 5 阶段会踩这个坑。

### 1.5 全局异常处理器

新建 `common/exception/GlobalExceptionHandler.java`：

```java
package com.example.mall.common.exception;

import com.example.mall.common.api.Result;
import com.example.mall.common.api.ResultCode;
import jakarta.validation.ConstraintViolationException;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.validation.BindException;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.MissingServletRequestParameterException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException;
import org.springframework.web.servlet.resource.NoResourceFoundException;

import java.util.stream.Collectors;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /**
     * 业务异常：可预期，warn 即可，不打堆栈。
     * 这里保留 BusinessException 里的业务码，前端可以精确判断。
     */
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        log.warn("业务异常: code={}, message={}", e.getCode(), e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    /** @RequestBody 参数校验失败 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleMethodArgumentNotValid(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(error -> error.getField() + ": " + error.getDefaultMessage())
                .collect(Collectors.joining("; "));
        log.warn("参数校验失败: {}", message);
        return Result.fail(ResultCode.BAD_REQUEST, message);
    }

    /** 表单/Query 参数绑定校验失败 */
    @ExceptionHandler(BindException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleBindException(BindException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(error -> error.getField() + ": " + error.getDefaultMessage())
                .collect(Collectors.joining("; "));
        log.warn("参数绑定失败: {}", message);
        return Result.fail(ResultCode.BAD_REQUEST, message);
    }

    /** 单参数校验失败，如 @RequestParam @Min(1) */
    @ExceptionHandler(ConstraintViolationException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleConstraintViolation(ConstraintViolationException e) {
        String message = e.getConstraintViolations().stream()
                .map(v -> v.getPropertyPath() + ": " + v.getMessage())
                .collect(Collectors.joining("; "));
        log.warn("单参数校验失败: {}", message);
        return Result.fail(ResultCode.BAD_REQUEST, message);
    }

    @ExceptionHandler(MissingServletRequestParameterException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleMissingParam(MissingServletRequestParameterException e) {
        return Result.fail(ResultCode.BAD_REQUEST, "缺少参数: " + e.getParameterName());
    }

    /** 路径变量类型错误，如 /api/products/abc */
    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleTypeMismatch(MethodArgumentTypeMismatchException e) {
        return Result.fail(ResultCode.BAD_REQUEST, "参数类型错误: " + e.getName());
    }

    /** 请求体不是合法 JSON */
    @ExceptionHandler(HttpMessageNotReadableException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleNotReadable(HttpMessageNotReadableException e) {
        // 不打印 e.getMessage()，避免把请求体片段（可能含手机号）写进日志
        log.warn("请求体解析失败");
        return Result.fail(ResultCode.BAD_REQUEST, "请求体格式错误");
    }

    /** 接口不存在：避免被下面的 Exception 兜底吞成 500 */
    @ExceptionHandler(NoResourceFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public Result<Void> handleNoResource(NoResourceFoundException e) {
        return Result.fail(ResultCode.NOT_FOUND, "接口不存在");
    }

    /** 兜底：未预期异常，必须记录完整堆栈 */
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.fail(ResultCode.INTERNAL_ERROR);
    }
}
```

**三个关键点：**

- 业务异常用 `log.warn`，不打堆栈；系统异常用 `log.error`，**必须把异常对象作为最后一个参数**，否则没有堆栈。
- 兜底异常不要返回 `e.getMessage()`，可能泄露 SQL、文件路径、内网地址。
- `@ExceptionHandler(Exception.class)` 会把 404 也吞掉，所以单独处理 `NoResourceFoundException`，否则前端会收到 500，排错方向全错。

```java
package com.example.mall.common.validation;

import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;

import java.util.regex.Pattern;

public class PhoneValidator implements ConstraintValidator<Phone, String> {

    private static final Pattern PATTERN = Pattern.compile("^1[3-9]\\d{9}$");

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        // 字段可选：不传（null）就跳过校验；空字符串仍然算错误
        if (value == null) {
            return true;
        }
        return PATTERN.matcher(value).matches();
    }
}
```

```java
package com.example.mall.modules.product.service.impl;

import com.example.mall.common.api.ResultCode;
import com.example.mall.common.exception.BusinessException;
import com.example.mall.modules.product.dto.ProductCreateDTO;
import com.example.mall.modules.product.entity.Product;
import com.example.mall.modules.product.mapper.ProductMapper;
import com.example.mall.modules.product.service.ProductService;
import com.example.mall.modules.product.vo.ProductVO;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.BeanUtils;
import org.springframework.stereotype.Service;

@Slf4j
@Service
@RequiredArgsConstructor
public class ProductServiceImpl implements ProductService {

    private final ProductMapper productMapper;

    @Override
    public ProductVO create(ProductCreateDTO dto) {
        log.info("创建商品, name={}", dto.getName());

        Product product = new Product();
        BeanUtils.copyProperties(dto, product);
        product.setStatus(1);
        product.setVersion(0);
        product.setDeleted(0);

        productMapper.insert(product);
        log.info("创建商品成功, id={}", product.getId());
        return toVO(product);
    }

    @Override
    public ProductVO getById(Long id) {
        Product product = productMapper.selectById(id);
        if (product == null) {
            throw new BusinessException(ResultCode.PRODUCT_NOT_FOUND);
        }
        return toVO(product);
    }

    private ProductVO toVO(Product product) {
        ProductVO vo = new ProductVO();
        BeanUtils.copyProperties(product, vo);
        vo.setStatusText(Integer.valueOf(1).equals(product.getStatus()) ? "上架" : "下架");
        vo.setContactPhone(maskPhone(product.getContactPhone()));
        return vo;
    }

    private String maskPhone(String phone) {
        if (phone == null || phone.length() != 11) {
            return phone;
        }
        return phone.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
    }
}
```

> **`BeanUtils.copyProperties` 的参数顺序是 `(源, 目标)`。**
> Spring 用的是 `org.springframework.beans.BeanUtils`；Apache Commons 的同名方法顺序相反，是 `(目标, 源)`。混用会得到一堆 null，而且不报错。

```java
package com.example.mall.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.OptimisticLockerInnerInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        // 1. 分页插件：不注册就不会有 LIMIT，total 也会是 0
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));

        // 2. 乐观锁插件：配合实体上的 @Version
        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());

        return interceptor;
    }
}
```

> **坑 3-1：分页插件没注册。**
> 现象是查询返回全部数据、`total=0`，或者 SQL 里没有 `LIMIT`。检查这个 `@Bean` 是否被扫描到。

### 3.2 自动填充

新建 `config/MyMetaObjectHandler.java`：

```java
package com.example.mall.config;

import com.baomidou.mybatisplus.core.handlers.MetaObjectHandler;
import org.apache.ibatis.reflection.MetaObject;
import org.springframework.stereotype.Component;

import java.time.LocalDateTime;

@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        LocalDateTime now = LocalDateTime.now();
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, now);
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, now);
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        // strictUpdateFill 只在字段为 null 时填充；更新时实体通常已带旧的 updateTime，
        // 所以这里用 setFieldValByName 强制覆盖。
        this.setFieldValByName("updateTime", LocalDateTime.now(), metaObject);
    }
}
```

实体上的两个注解已经在第 2 阶段写好了：

```java
@TableField(fill = FieldFill.INSERT)
private LocalDateTime createTime;

@TableField(fill = FieldFill.INSERT_UPDATE)
private LocalDateTime updateTime;
```

> **坑 3-2：自动填充不生效。**
> 常见原因：`MyMetaObjectHandler` 没加 `@Component`；字段名写错（必须是 `createTime`，不是 `create_time`）；`strictInsertFill` 只在字段为 null 时填充，如果你手动 set 了值，它不会覆盖。

把 `ProductServiceImpl` 替换成完整版本：

```java
package com.example.mall.modules.product.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.example.mall.common.api.PageResult;
import com.example.mall.common.api.ResultCode;
import com.example.mall.common.exception.BusinessException;
import com.example.mall.config.ProductProperties;
import com.example.mall.modules.product.dto.ProductCreateDTO;
import com.example.mall.modules.product.dto.ProductQueryDTO;
import com.example.mall.modules.product.dto.ProductUpdateDTO;
import com.example.mall.modules.product.entity.Product;
import com.example.mall.modules.product.mapper.ProductMapper;
import com.example.mall.modules.product.service.ProductService;
import com.example.mall.modules.product.vo.ProductVO;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.BeanUtils;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

import java.util.List;

@Slf4j
@Service
@RequiredArgsConstructor
public class ProductServiceImpl implements ProductService {

    private final ProductMapper productMapper;
    private final ProductProperties productProperties;

    @Override
    public ProductVO create(ProductCreateDTO dto) {
        log.info("创建商品, name={}", dto.getName());

        Product product = new Product();
        BeanUtils.copyProperties(dto, product);
        product.setStatus(1);
        product.setVersion(0);
        product.setDeleted(0);

        productMapper.insert(product);
        log.info("创建商品成功, id={}", product.getId());
        return toVO(product);
    }

    @Override
    public ProductVO getById(Long id) {
        Product product = productMapper.selectById(id);
        if (product == null) {
            throw new BusinessException(ResultCode.PRODUCT_NOT_FOUND);
        }
        return toVO(product);
    }

    @Override
    public PageResult<ProductVO> page(ProductQueryDTO query) {
        if (query.getMinPrice() != null && query.getMaxPrice() != null
                && query.getMinPrice().compareTo(query.getMaxPrice()) > 0) {
            throw new BusinessException(ResultCode.BAD_REQUEST, "最低价不能大于最高价");
        }

        // 双重保险：DTO 上有 @Max(100)，配置里再兜一层
        long pageSize = Math.min(query.getPageSize(), productProperties.getPageSizeLimit());
        Page<Product> page = new Page<>(query.getPageNum(), pageSize);

        LambdaQueryWrapper<Product> wrapper = new LambdaQueryWrapper<Product>()
                .like(StringUtils.hasText(query.getKeyword()), Product::getName, query.getKeyword())
                .ge(query.getMinPrice() != null, Product::getPrice, query.getMinPrice())
                .le(query.getMaxPrice() != null, Product::getPrice, query.getMaxPrice())
                .eq(query.getStatus() != null, Product::getStatus, query.getStatus())
                .orderByDesc(Product::getCreateTime)
                .orderByDesc(Product::getId);

        Page<Product> result = productMapper.selectPage(page, wrapper);
        List<ProductVO> records = result.getRecords().stream()
                .map(this::toVO)
                .toList();

        return PageResult.of(result.getTotal(), result.getCurrent(), result.getSize(), records);
    }

    @Override
    public ProductVO update(Long id, ProductUpdateDTO dto) {
        Product product = productMapper.selectById(id);
        if (product == null) {
            throw new BusinessException(ResultCode.PRODUCT_NOT_FOUND);
        }

        BeanUtils.copyProperties(dto, product);
        int affected = productMapper.updateById(product);
        if (affected == 0) {
            // 版本号对不上，说明有人在你查询之后改过这条数据
            throw new BusinessException(ResultCode.CONFLICT, "商品已被其他请求修改，请刷新后重试");
        }

        Product updated = productMapper.selectById(id);
        if (updated == null) {
            throw new BusinessException(ResultCode.PRODUCT_NOT_FOUND);
        }
        log.info("修改商品成功, id={}", id);
        return toVO(updated);
    }

    @Override
    public void delete(Long id) {
        Product product = productMapper.selectById(id);
        if (product == null) {
            throw new BusinessException(ResultCode.PRODUCT_NOT_FOUND);
        }

        int affected = productMapper.deleteById(id);
        if (affected == 0) {
            throw new BusinessException(ResultCode.NOT_FOUND, "商品已被删除");
        }
        log.info("删除商品, id={}", id);
    }

    private ProductVO toVO(Product product) {
        ProductVO vo = new ProductVO();
        BeanUtils.copyProperties(product, vo);
        vo.setStatusText(Integer.valueOf(1).equals(product.getStatus()) ? "上架" : "下架");
        vo.setContactPhone(maskPhone(product.getContactPhone()));
        vo.setStockWarning(product.getStock() != null
                && product.getStock() <= productProperties.getLowStockThreshold());
        return vo;
    }

    private String maskPhone(String phone) {
        if (phone == null || phone.length() != 11) {
            return phone;
        }
        return phone.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
    }
}
```

**几个容易忽略的点：**

- `like(condition, column, value)` 的第一个参数是布尔值，条件不成立时不会拼这段 SQL。
- 价格区间用 `ge/le`，不要用字符串拼接。
- `orderByDesc` 可以连续调用，生成 `ORDER BY create_time DESC, id DESC`，避免同一时间创建的数据顺序不稳定。
- `updateById` 默认**忽略 null 字段**，所以 DTO 里没传的 `description` 不会被改成 null。代价是：想主动清空某个字段，用 `updateById` 做不到，要改用 `UpdateWrapper` 显式 `set`。

### 3.7 验证自动填充和乐观锁

**1）新增一条商品**，然后查数据库：

```sql
SELECT id, name, create_time, update_time, version FROM product ORDER BY id DESC LIMIT 1;
```

`create_time` 和 `update_time` 应该非常接近，且是 Java 写入的时间。

**2）修改商品**

```bash
curl -i -X PUT http://localhost:8080/api/products/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "机械键盘 Pro",
    "price": 459.00,
    "contactPhone": "13800138000",
    "description": "升级热插拔"
  }'
```

预期：HTTP 200，`code=0`。数据库里：

```sql
SELECT id, name, price, version, update_time FROM product WHERE id = 1;
```

应该看到 `version` 从 0 变成 1，`update_time` 更新了。控制台 SQL 里能看到：

```sql
UPDATE product
SET name=?, price=?, ..., version=?, update_time=?
WHERE id=? AND version=? AND deleted=0
```

这就是乐观锁：更新时带上旧版本号，`version` 自增。并发情况下，后到的请求会因为 `version` 不匹配而更新 0 行。

**3）模拟版本冲突（可选，但强烈建议做）**

开两个数据库会话，或者在两次请求之间手动改库：

```sql
-- 在请求发出前，手动把 version 改大
UPDATE product SET version = version + 1 WHERE id = 1;
```

然后再执行上面的 PUT。预期返回 `code=40900`，`message=商品已被其他请求修改，请刷新后重试`。

### 3.9 逻辑删除 + 唯一索引的坑（选做实验）

教程 1.9.4 提到：逻辑删除后，唯一索引会导致同名记录无法再插入。亲手验证一次：

```sql
-- 1. 先恢复 id=2，方便实验
UPDATE product SET deleted = 0 WHERE id = 2;

-- 2. 给 name 加唯一索引
ALTER TABLE product ADD UNIQUE KEY uk_name (name);
```

然后：

1. 调用 DELETE 删除"无线鼠标"（逻辑删除，`deleted=1`）。
2. 再 POST 新增一个同名"无线鼠标"。

预期：插入失败，报 `Duplicate entry '无线鼠标' for key 'uk_name'`。因为唯一索引只看 `name`，不看 `deleted`。

常见修法：

```sql
ALTER TABLE product DROP INDEX uk_name;
ALTER TABLE product ADD UNIQUE KEY uk_name_deleted (name, deleted);
```

但这仍然有局限：同名的记录最多只能"删除一次"，第二次删除会撞 `(name, 1)`。更彻底的做法是把 `deleted` 设计成"删除时间戳"或"删除时写入唯一后缀"，这属于进阶话题，本章知道有坑即可。实验结束后建议删掉唯一索引：

```sql
ALTER TABLE product DROP INDEX uk_name_deleted;
```

### 3.10 本阶段坑

1. **分页不生效**：插件没注册，或 `DbType` 写错。
2. **`total` 一直是 0**：同上；也可能用了自定义 SQL 但没走分页插件。
3. **逻辑删除不生效**：`@TableLogic` 没加，或 `application.yml` 的 `logic-delete-field` 拼错。
4. **自动填充不生效**：Handler 不是 Bean；字段名不对；字段已有值。
5. **乐观锁不生效**：实体没加 `@Version`，或插件没注册，或更新时实体里 `version` 是 null。
6. **`updateById` 无法把字段改成 null**：默认忽略 null，需要 `UpdateWrapper`。
7. **`like` 把 `%` 拼进用户输入**：MyBatis-Plus 的 `like` 会参数化，不会 SQL 注入；但用户输入 `%` 会变成通配符，是否需要转义看业务。

## 第 4 阶段：日志与链路 ID

**本阶段目标**：日志同时输出到控制台和滚动文件；每个请求有一个 `traceId`，能把一次请求的多行日志串起来。

**预计用时**：1 小时。

### 4.1 用 SLF4J，不用 `System.out`

业务代码里统一用 Lombok 的 `@Slf4j`：

```java
@Slf4j
@Service
public class ProductServiceImpl {
    public ProductVO getById(Long id) {
        log.info("查询商品, id={}", id);
        // ...
    }
}
```

**为什么用 `{}` 占位符？**

- 日志级别没开启时，不会执行字符串拼接；
- 避免 `"id=" + id` 产生大量临时字符串；
- 参数和模板分开，日志更易读。

**不要这样写：**

```java
log.info("查询商品, id=" + id);          // 每次都拼接
log.error("系统异常: " + e.getMessage()); // 没有堆栈
```

### 4.2 `logback-spring.xml`

在 `src/main/resources` 下新建：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <property name="LOG_HOME" value="./logs"/>
    <property name="APP_NAME" value="mall-product"/>
    <property name="LOG_PATTERN"
              value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%X{traceId:-}] %logger{36} - %msg%n"/>

    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_HOME}/${APP_NAME}.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${LOG_HOME}/${APP_NAME}-%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxFileSize>100MB</maxFileSize>
            <maxHistory>15</maxHistory>
            <totalSizeCap>2GB</totalSizeCap>
        </rollingPolicy>
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </root>

    <!-- logback-spring.xml 才支持 springProfile -->
    <springProfile name="dev">
        <logger name="com.example.mall" level="DEBUG"/>
    </springProfile>

    <springProfile name="prod">
        <logger name="com.example.mall" level="INFO"/>
    </springProfile>
</configuration>
```

> **坑 4-1：文件名必须是 `logback-spring.xml`。**
> `logback.xml` 会被 Logback 自己先加载，Spring Boot 的 `<springProfile>` 扩展不生效，启动时会报错或 profile 不按预期工作。

> **坑 4-2：日志文件路径是相对路径。**
> `./logs` 相对于**进程工作目录**。IDEA 里运行通常是项目根目录；`java -jar` 时是你执行命令的目录。生产环境建议用绝对路径或挂载卷。

### 4.3 TraceId 过滤器

新建 `common/log/TraceIdFilter.java`：

```java
package com.example.mall.common.log;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.MDC;
import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;
import org.springframework.util.StringUtils;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;
import java.util.UUID;
import java.util.regex.Pattern;

@Component
@Order(Ordered.HIGHEST_PRECEDENCE)
public class TraceIdFilter extends OncePerRequestFilter {

    public static final String TRACE_ID = "traceId";
    public static final String TRACE_HEADER = "X-Trace-Id";

    /** 只接受安全字符，防止把换行等注入日志 */
    private static final Pattern VALID_TRACE_ID = Pattern.compile("^[a-zA-Z0-9-]{1,64}$");

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        String traceId = request.getHeader(TRACE_HEADER);
        if (!StringUtils.hasText(traceId) || !VALID_TRACE_ID.matcher(traceId).matches()) {
            traceId = UUID.randomUUID().toString().replace("-", "").substring(0, 16);
        }

        MDC.put(TRACE_ID, traceId);
        response.setHeader(TRACE_HEADER, traceId);

        try {
            filterChain.doFilter(request, response);
        } finally {
            // 线程池复用线程，必须清理，否则下一个请求会拿到旧 traceId
            MDC.remove(TRACE_ID);
        }
    }
}
```

**设计要点：**

- 上游传了合法的 `X-Trace-Id` 就复用，方便网关/前端串联链路；没传就生成。
- 响应头也带回去，前端报错时可以把它贴给后端。
- `finally` 里必须 `MDC.remove`。
- `MDC` 基于 `ThreadLocal`，**异步线程拿不到**。后面章节会用 `TaskDecorator` 或链路追踪组件解决。

```java
package com.example.mall.modules.product.service.impl;

import com.example.mall.common.api.ResultCode;
import com.example.mall.common.exception.BusinessException;
import com.example.mall.modules.product.entity.Product;
import com.example.mall.modules.product.entity.StockLog;
import com.example.mall.modules.product.mapper.ProductMapper;
import com.example.mall.modules.product.mapper.StockLogMapper;
import com.example.mall.modules.product.service.StockService;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Slf4j
@Service
@RequiredArgsConstructor
public class StockServiceImpl implements StockService {

    private final ProductMapper productMapper;
    private final StockLogMapper stockLogMapper;

    /**
     * 扣库存 + 写流水，两件事必须在同一个事务里：
     * 库存扣了但流水没写，或者流水写了但库存没扣，都是脏数据。
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void decrease(Long productId, int count, String reason) {
        Product product = productMapper.selectById(productId);
        if (product == null) {
            throw new BusinessException(ResultCode.PRODUCT_NOT_FOUND);
        }
        if (!Integer.valueOf(1).equals(product.getStatus())) {
            throw new BusinessException(ResultCode.PRODUCT_OFF_SHELF);
        }

        // 真正的防超卖：条件更新，一条 SQL 完成"判断 + 扣减"
        int affected = productMapper.decreaseStock(productId, count);
        if (affected == 0) {
            throw new BusinessException(ResultCode.PRODUCT_STOCK_NOT_ENOUGH);
        }

        StockLog stockLog = new StockLog();
        stockLog.setProductId(productId);
        stockLog.setChangeAmount(-count);
        stockLog.setBeforeStock(product.getStock());
        stockLog.setAfterStock(product.getStock() - count);
        stockLog.setReason(reason);
        stockLogMapper.insert(stockLog);

        log.info("扣减库存成功, productId={}, count={}, before={}, after={}",
                productId, count, product.getStock(), product.getStock() - count);
    }
}
```

**这里有两层库存校验，职责不同：**

| 校验 | 作用 |
|---|---|
| `selectById` 后的 `status` 判断 | 业务规则：下架商品不能扣库存，返回明确提示 |
| `decreaseStock` 的 `stock >= count` | 并发安全：数据库层面保证不会扣成负数 |

> **注意 `beforeStock` 的精度问题**：`selectById` 查到的库存，到真正 UPDATE 之间，可能被别的请求改了。所以流水里的 `before/after` 在高并发下可能不是精确值。生产项目通常用 `SELECT ... FOR UPDATE` 锁行，或者扣减后重新查询。本章先把这个"不完美"记下来，第 02 章讲锁和事务隔离时会解决。

```java
import com.example.mall.modules.product.entity.StockLog;
import com.example.mall.modules.product.mapper.ProductMapper;
import com.example.mall.modules.product.mapper.StockLogMapper;
import lombok.RequiredArgsConstructor;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.transaction.interceptor.TransactionAspectSupport;

@Slf4j
@Profile("dev")
@Service
@RequiredArgsConstructor
public class TxLabService {

    private final ProductMapper productMapper;
    private final StockLogMapper stockLogMapper;
    private final TxInnerService txInnerService;

    // ==================== 实验 0：正常事务回滚 ====================

    /**
     * 扣库存 + 写流水后抛异常。
     * 预期：库存不变，流水也没有。
     */
    @Transactional(rollbackFor = Exception.class)
    public void stockDecreaseThenThrow(Long productId, int count) {
        productMapper.decreaseStock(productId, count);
        writeLog("TX-STOCK-ROLLBACK");
        throw new RuntimeException("模拟库存已扣、流水已写，然后失败");
    }

    public void selfInvocation() {

        this.innerWriteThenThrow("TX-SELF");
    }

    @Transactional(rollbackFor = Exception.class)
    public void innerWriteThenThrow(String reason) {
        writeLog(reason);
        throw new RuntimeException("inner boom");
    }

    // ==================== 实验 2：拆到独立 Bean（修复自调用） ====================

    public void selfInvocationFixed() {
        txInnerService.writeThenThrow("TX-SELF-FIXED");
    }

    // ==================== 实验 3：异常被自己 catch ====================

    @Transactional(rollbackFor = Exception.class)
    public void catchAndSwallow() {
        writeLog("TX-CATCH");
        try {
            throw new IllegalStateException("boom");
        } catch (Exception e) {
            // 吞掉异常，事务管理器根本不知道出过错，方法正常返回 -> 提交

        }

    // ==================== 实验 4：catch 后手动标记回滚 ====================

    @Transactional(rollbackFor = Exception.class)
    public void catchAndRollback() {
        writeLog("TX-CATCH-FIX");
        try {
            throw new IllegalStateException("boom");
        } catch (Exception e) {
            log.warn("捕获异常，但标记事务回滚: {}", e.getMessage());
```

### 5.7 开始实验

**统一操作流程**（每个实验都重复）：

1. 清空流水表：
   ```sql
   DELETE FROM product_stock_log;
   ```
2. 记录当前库存：
   ```sql
   SELECT id, stock FROM product WHERE id = 1;
   ```
3. 调用实验接口（会返回 500，这是预期的，因为实验方法故意抛异常）。
4. 查流水：
   ```sql
   SELECT id, product_id, change_amount, reason FROM product_stock_log ORDER BY id;
   ```
5. 对照预期，把结果填进下面的表格。

#### 实验 0：正常事务回滚

```bash
curl -i "http://localhost:8080/api/lab/tx/stock-rollback?productId=1&count=5"
```

预期：

- 接口返回 500（故意抛异常）；
- `product.stock` **不变**；
- `product_stock_log` **没有** `TX-STOCK-ROLLBACK`。

结论：`decreaseStock` 和 `insert` 在同一个事务里，异常导致两者一起回滚。

#### 实验 1：同类内自调用

```bash
curl -i http://localhost:8080/api/lab/tx/self
```

预期：

- 接口返回 500；
- 流水表**有** `TX-SELF`。

原因：`selfInvocation()` 里的 `this.innerWriteThenThrow(...)` 走的是原始对象，不是 Spring 代理，`@Transactional` 被忽略。插入语句在 MyBatis-Spring 的非事务模式下自动提交，所以异常发生后数据仍在。

#### 实验 2：拆到独立 Bean

```bash
curl -i http://localhost:8080/api/lab/tx/self-fixed
```

预期：

- 接口返回 500；
- 流水表**没有** `TX-SELF-FIXED`。

原因：`txInnerService` 是代理对象，`@Transactional` 生效，异常触发回滚。

#### 实验 3：异常被吞

```bash
curl -i http://localhost:8080/api/lab/tx/catch
```

预期：

- 接口返回 **200**（方法正常结束）；
- 流水表**有** `TX-CATCH`。

原因：异常在方法内部被 catch，没有传播给事务拦截器，事务拦截器认为方法成功，提交。

#### 实验 4：catch 后标记回滚

```bash
curl -i http://localhost:8080/api/lab/tx/catch-fix
```

预期：

- 接口返回 200（`setRollbackOnly` 不会重新抛异常）；
- 流水表**没有** `TX-CATCH-FIX`。

原因：`setRollbackOnly()` 告诉事务管理器"提交时改成回滚"，即使方法正常返回。

#### 实验 5：受检异常

```bash
curl -i http://localhost:8080/api/lab/tx/checked
```

预期：

- 接口返回 500；
- 流水表**有** `TX-CHECKED`。

原因：`@Transactional` 默认只对 `RuntimeException` 和 `Error` 回滚，受检异常不会触发回滚。这是最容易被忽略的坑。

#### 实验 6：`rollbackFor = Exception.class`

```bash
curl -i http://localhost:8080/api/lab/tx/checked-fix
```

预期：

- 接口返回 500；
- 流水表**没有** `TX-CHECKED-FIX`。

#### 实验 7：多线程

```bash
curl -i http://localhost:8080/api/lab/tx/thread
```

预期：

- 接口返回 500；
- 流水表**没有** `TX-THREAD-MAIN`；
- 流水表**有** `TX-THREAD-CHILD`。

原因：事务绑定在 `ThreadLocal` 上，子线程不在父线程的事务里。子线程的插入是独立提交的，主线程回滚管不到它。

#### 实验 8：`REQUIRES_NEW`

```bash
curl -i http://localhost:8080/api/lab/tx/requires-new
```

预期：

- 接口返回 500；
- 流水表**有** `TX-REQUIRES-NEW`；
- 流水表**没有** `TX-REQUIRES-MAIN`。

原因：`REQUIRES_NEW` 挂起外层事务，开了一个新事务。新事务先提交；外层随后回滚，互不影响。

### 5.9 事务传播行为速查

| 传播行为 | 含义 | 典型场景 |
|---|---|---|
| `REQUIRED`（默认） | 有事务就加入，没有就新建 | 大多数业务 |
| `REQUIRES_NEW` | 总是新建事务，挂起当前事务 | 审计日志、通知，不希望随主事务回滚 |
| `NESTED` | 嵌套事务，用保存点 | 部分失败不影响外层（少数场景） |
| `SUPPORTS` | 有就加入，没有就非事务运行 | 查询 |
| `NOT_SUPPORTED` | 非事务运行，挂起当前事务 | 耗时操作 |
| `MANDATORY` | 必须在事务中，否则报错 | 强制约束 |
| `NEVER` | 不能在事务中 | 强制约束 |

> `REQUIRES_NEW` 会占用第二个数据库连接。高并发下如果连接池很小，可能自己把自己等死。使用前先想清楚：这个操作真的需要独立提交吗？

### 5.10 大事务问题

一个事务里做了：

1. 查数据库（10ms）；
2. 调远程接口（500ms）；
3. 发短信（1000ms）；
4. 写数据库。

后果：

- 数据库连接被占用 1.5 秒以上，连接池很快耗尽；
- 行锁/间隙锁持有时间长，其他事务等待；
- 一旦远程调用超时，整个事务回滚，但短信已经发出去了，数据不一致。

**原则**：事务里只放数据库操作。远程调用、消息发送、文件 IO 放到事务外，用"本地消息表 + 重试"或"事务提交后的事件"保证最终一致（第 07 章展开）。

### 5.11 本阶段坑

1. **`@Transactional` 加在 private 方法上**：CGLIB 代理不了 private，注解无效。必须是 `public`。
2. **`final` / `static` 方法**：同理，无法代理。
3. **`new` 出来的对象调用事务方法**：没有代理，注解无效。对象必须交给 Spring 管理。
4. **同类内自调用**：最高频的坑，见实验 1。
5. **异常被 catch 掉**：见实验 3。
6. **受检异常没配 `rollbackFor`**：见实验 5。
7. **多线程**：见实验 7。
8. **表引擎是 MyISAM**：不支持事务。本项目用 InnoDB。
9. **`@Transactional` 写在接口上**：建议写在实现类的方法上，AOP 代理行为更可控。
10. **事务方法里做了远程调用**：见 5.10。
11. **`setRollbackOnly` 后继续写数据库**：后续写入也在同一事务里，最终一起回滚；不要以为标记后还能提交一部分。

### 6.4 优雅停机

配置见 `application.yml`：

```yaml
server:
  shutdown: graceful

spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s
```

效果：

- 收到停止信号后，Tomcat 先**拒绝新请求**；
- 已经进来的请求继续处理，最多等 30 秒；
- 处理完再关闭连接池、退出进程。

没有这个配置时，进程一停，正在处理的请求直接断开，调用方收到大量 502/连接重置。上线滚动发布时尤其明显。

> 优雅停机在本地不容易直观验证。你可以写一个 `Thread.sleep(5000)` 的测试接口，启动后发请求，然后在请求处理期间按 `Ctrl+C`，观察请求是否还能正常返回。验证完把测试接口删掉。

### 6.5 本阶段坑

1. **生产配置写死密码**：用环境变量或配置中心，绝不进 Git。
2. **Actuator 暴露过多**：只开 `health,info,metrics`，生产不要 `show-details: always`。
3. **`spring.profiles.active` 写死在 `application.yml`**：部署时用命令行或环境变量覆盖，不要改代码重新打包。
4. **配置项拼写错误**：`@ConfigurationProperties` 默认忽略未知字段，写错了不报错，只是不生效。可以加 `@Validated` 和校验注解提前发现。
5. **改了配置没重启**：`@ConfigurationProperties` 默认不支持热更新；需要动态刷新要配合配置中心。

### 7.5 教程练习题答案与提示

#### 练习 1：把 CRUD 改造成本章结构

本项目就是答案。重点检查：

- 是否有 `common/api`、`common/exception`、`config`、`modules` 四层；
- Controller 是否只做"接参 → 调 Service → 包 Result"；
- 入参是否 DTO，出参是否 VO；
- 是否有全局异常处理。

#### 练习 2：自调用 + `@Transactional`

见第 5 阶段实验 1 和实验 2。关键结论：

- `this.inner()` 不走代理，事务不生效；
- 修复方式：拆到另一个 Bean（推荐）、注入自己（`@Lazy`）、`AopContext.currentProxy()`（需要 `@EnableAspectJAutoProxy(exposeProxy = true)`）。

#### 练习 3：分页 + 关键字 + 价格区间

见 3.4 的 `page` 方法和 3.6 的验证。注意：

- `like` 的模糊查询要参数化；
- 价格区间用 `ge/le`；
- `pageSize` 要有上限，防止拖库。

#### 练习 4：自定义 `@Phone`

见 2.3。关键点：

- 注解上必须有 `message()`、`groups()`、`payload()`；

#### 练习 6：为什么业务异常用 `warn` 而不是 `error`？

参考答案：

**业务异常是"可预期的失败"**，比如用户输入错、库存不足、商品已下架。它不需要工程师半夜起来处理，数量可能很多，打 `error` 会造成：

1. **告警疲劳**：监控按 `ERROR` 数量报警，业务异常一多，真正的系统故障被淹没；
2. **日志膨胀**：每个业务异常都打堆栈，磁盘和检索成本急剧上升；
3. **误导排错**：新人看到满屏 ERROR，会以为系统挂了，实际只是用户输错了；
4. **堆栈无意义**：业务异常是主动 `throw` 的，堆栈指向业务代码，不提供额外信息。

**系统异常是"未预期的故障"**，比如空指针、数据库连不上、序列化失败。它需要人介入，必须 `error` + 完整堆栈 + 告警。

一句话：**warn 给业务看，error 给运维看。**
