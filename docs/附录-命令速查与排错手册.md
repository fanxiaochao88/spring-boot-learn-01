## A.1 Docker 命令速查

### 镜像

```bash
docker images                          # 本地镜像
docker pull mysql:8.0                  # 拉取
docker push registry/app:1.0           # 推送
docker rmi <image>                     # 删除镜像
docker image prune -a                  # 清理未使用镜像
docker build -t app:1.0 .              # 构建
docker history app:1.0                 # 查看镜像层
```

### 容器

```bash
docker ps                              # 运行中
docker ps -a                           # 全部
docker run -d --name app -p 8080:8080 app:1.0
docker run -it --rm ubuntu bash        # 临时交互容器，退出即删
docker stop app
docker start app
docker restart app
docker rm -f app
docker logs -f --tail 200 app
docker exec -it app sh
docker exec -it app env                # 查看环境变量
docker inspect app                     # 详细信息
docker stats                           # 资源占用
docker top app                         # 容器内进程
docker cp app:/app/logs ./logs         # 从容器拷文件
docker commit app app:snapshot         # 容器保存为镜像（不推荐生产）
```

### Compose

```bash
docker compose up -d
docker compose up -d --build           # 重新构建
docker compose ps
docker compose logs -f --tail 100
docker compose restart mysql
docker compose stop
docker compose down                    # 删除容器，保留卷
docker compose down -v                 # 删除容器 + 卷（数据丢失）
docker compose config                  # 校验并查看最终配置
```

### 卷与网络

```bash
docker volume ls
docker volume inspect roadmap_mysql-data
docker volume rm <volume>
docker network ls
docker network inspect roadmap_default
docker network create mall-net
```

### 清理

```bash
docker system df                       # 磁盘占用
docker system prune                    # 清理停止的容器、悬空镜像、未用网络
docker system prune -a --volumes       # 彻底清理（谨慎）
```

## A.3 MySQL 命令速查

### 连接与库表

```bash
mysql -h127.0.0.1 -P3306 -uroot -p
```

```sql
SHOW DATABASES;
CREATE DATABASE roadmap_db DEFAULT CHARSET utf8mb4;
USE roadmap_db;
SHOW TABLES;
DESC product;
SHOW CREATE TABLE product\G
SHOW INDEX FROM product;
SHOW TABLE STATUS LIKE 'product';
```

### 查询与优化

```sql
EXPLAIN SELECT * FROM product WHERE id = 1;
EXPLAIN ANALYZE SELECT ...;            -- MySQL 8.0.18+
SHOW PROCESSLIST;
SHOW FULL PROCESSLIST;
KILL <id>;
SHOW VARIABLES LIKE 'slow_query%';
SHOW VARIABLES LIKE 'long_query_time';
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;
SHOW ENGINE INNODB STATUS\G            -- 死锁、事务
SHOW STATUS LIKE 'Threads_connected';
SHOW STATUS LIKE 'Innodb_row_lock%';
```

### 事务

```sql
SELECT @@transaction_isolation;
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN;
COMMIT;
ROLLBACK;
SELECT * FROM product WHERE id = 1 FOR UPDATE;
```

### 备份与恢复

```bash
mysqldump -uroot -p123456 --single-transaction roadmap_db > backup.sql
mysql -uroot -p123456 roadmap_db < backup.sql

# Docker 环境
docker exec roadmap-mysql mysqldump -uroot -p123456 roadmap_db > backup.sql
docker exec -i roadmap-mysql mysql -uroot -p123456 roadmap_db < backup.sql
```

### 常用排查 SQL

```sql
-- 当前运行超过 5 秒的查询
SELECT id, user, host, db, command, time, state, info
FROM information_schema.processlist
WHERE command != 'Sleep' AND time > 5
ORDER BY time DESC;

-- 表大小
SELECT table_name,
       ROUND(data_length / 1024 / 1024, 2) AS data_mb,
       ROUND(index_length / 1024 / 1024, 2) AS index_mb,
       table_rows
FROM information_schema.tables
WHERE table_schema = 'roadmap_db'
ORDER BY data_length DESC;

-- 未使用的索引（需 performance_schema）
SELECT * FROM sys.schema_unused_indexes;
```

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --list
kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic order-created
kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic order-created --partitions 3 --replication-factor 1
kafka-topics.sh --bootstrap-server localhost:9092 \
  --alter --topic order-created --partitions 6
kafka-topics.sh --bootstrap-server localhost:9092 --delete --topic order-created
```

### 生产与消费

```bash
kafka-console-producer.sh --bootstrap-server localhost:9092 --topic order-created

kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic order-created --from-beginning

# 带 key
kafka-console-producer.sh --bootstrap-server localhost:9092 \
  --topic order-created --property parse.key=true --property key.separator=:

# 消费并显示 key
kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic order-created --property print.key=true --from-beginning
```

```bash

kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --describe --group points-group

# 重置 offset（危险，先停消费者）

  --group points-group --topic order-created --reset-offsets --to-earliest --execute
```

## A.6 Nacos OpenAPI 速查

```bash

curl "http://localhost:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=20"

  -d "dataId=product-service.yaml" \
  -d "group=DEFAULT_GROUP" \
```

## A.8 常见报错对照表

| 报错 | 常见原因 | 解决 |
|---|---|---|
| `Port 8080 was already in use` | 端口被占 | `netstat -ano | findstr 8080`（Windows）/ `lsof -i:8080`，杀进程或换端口 |
| `No provider available` | 服务未注册、服务名不一致 | 检查 Nacos、`spring.application.name`、namespace/group |
| `No instances available for xxx` | 无可用实例 | 服务是否启动、是否注册、是否健康 |
| `Load balancer does not contain an instance` | 缺 loadbalancer 依赖 | 加 `spring-cloud-starter-loadbalancer` |
| `Spring MVC found on classpath` | Gateway 引入了 web | 移除 `spring-boot-starter-web` |
| `No spring.config.import property has been defined` | 用了 nacos-config 没配 import | 加 `spring.config.import` |
| `java.lang.ClassNotFoundException: javax.servlet...` | Spring Boot 3 用了 javax | 改成 `jakarta.servlet` |
| `NoSuchMethodError` | 依赖版本冲突 | `mvn dependency:tree` 排查，统一版本 |
| `Cannot determine embedded database driver` | 缺数据源配置 | 检查 `spring.datasource` |
| `Access denied for user 'root'@'localhost'` | 密码/权限错误 | 检查密码、host 授权 |
| `Public Key Retrieval is not allowed` | MySQL 8 认证 | JDBC URL 加 `allowPublicKeyRetrieval=true&useSSL=false` |
| `Communications link failure` | MySQL 地址/端口/网络 | 检查 host、port、防火墙、容器网络 |
| `Table 'xxx' doesn't exist` | 库/表没建、连错库 | 检查 `init.sql`、`USE db` |
| `Duplicate entry 'x' for key 'uk_...'` | 唯一索引冲突 | 通常是幂等逻辑，捕获处理 |
| `Deadlock found when trying to get lock` | 死锁 | 固定加锁顺序、缩短事务、加索引 |
| `Lock wait timeout exceeded` | 锁等待超时 | 查 `SHOW ENGINE INNODB STATUS`、长事务 |
| `RedisConnectionFailureException` | Redis 未启动/地址错误 | 检查容器、host、password |
| `NOAUTH Authentication required` | Redis 需要密码 | 配置 password |
| `WRONGTYPE Operation against a key` | 对同一 key 用了不同类型 | 检查 key 设计 |
| `Kafka: Connection to node -1 could not be established` | `advertised.listeners` 错 | 配 EXTERNAL 监听 |
| `ClassCastException: LinkedHashMap cannot be cast` | JSON 反序列化无类型信息 | 配置类型信息或指定类型反序列化 |
| `JsonParseException` | JSON 格式/字段不匹配 | 检查消息格式和版本兼容 |
| `ListenerExecutionFailedException` | 消费者处理异常 | 看堆栈，配重试和死信 |
| `Offset commit cannot be completed... rebalance` | 处理时间超 `max.poll.interval.ms` | 调大或减少 `max.poll.records` |
| `Read timed out`（Feign） | 下游慢/超时设置短 | 调整 `read-timeout`、优化下游 |
| `Blocked by Sentinel (flow limiting)` | 触发限流 | 调整阈值或用户提示 |
| `401 Unauthorized` | token 缺失/过期 | 检查网关白名单、token 有效期 |
| `CORS policy: No 'Access-Control-Allow-Origin'` | 跨域未配置/重复配置 | 网关或 Nginx 只配一处 |
| `OutOfMemoryError: Java heap space` | 内存不足/泄漏 | 调 JVM、查大对象、`jmap` 分析 |
| `GC overhead limit exceeded` | GC 频繁但回收不了 | 查内存泄漏、调堆 |
| `Container exited with code 137` | 被 OOM Killer 杀 | 加内存限制或调 JVM |
| `permission denied` | 文件权限 | `chmod`/`chown` |
| `No space left on device` | 磁盘满 | 清理日志/镜像：`docker system prune` |

## A.9 排错方法论

遇到问题不要慌，按这个顺序：

```text
1. 读完整报错
   - 最后一行是直接原因，向上找 "Caused by"
   - 看异常类型、类名、行号

2. 定位范围
   - 是启动失败还是运行时报错？
   - 是单个接口还是全部接口？
   - 是本地还是容器？是开发还是生产？

3. 看日志
   - 应用日志：ERROR 前后 50 行
   - 中间件日志：MySQL、Redis、Nacos、Kafka
   - 容器日志：docker logs
   - 访问日志：Nginx、Gateway

4. 验证假设
   - 网络：curl / telnet 端口
   - 配置：打印生效配置（Actuator env）
   - 依赖：mvn dependency:tree
   - 数据：直接查库/查 Redis

5. 缩小范围
   - 注释掉可疑代码
   - 换一个接口/服务对比
   - 本地复现

6. 修复并验证
   - 写一个能复现的测试
   - 修复后跑测试 + 手工验证
   - 加监控/告警防止再次发生

7. 记录
   - 现象、原因、解决、预防
   - 下次遇到同类问题直接查笔记
```

### 三个高频排查命令

```bash
# 1. 看端口
netstat -tlnp | grep 8080          # Linux
netstat -ano | findstr 8080        # Windows

# 2. 看依赖冲突
mvn dependency:tree -Dincludes=org.springframework

# 3. 看生效配置
curl http://localhost:8081/actuator/env | jq '.activeProfiles'
```
