## 11.2 接下来学什么

### 11.2.1 优先级建议

```text
第一优先级（找工作必备）
  ├── Java 基础深入：集合、并发、JVM 基础
  ├── Spring 核心：IOC、AOP、事务、MVC 流程
  ├── MySQL：索引、事务、锁、优化
  └── 项目：把第 10 章做扎实，能讲 30 分钟

第二优先级（工作常用）
  ├── Redis 深入：持久化、集群、淘汰
  ├── Kafka / RocketMQ 深入：可靠性、顺序、事务
  ├── 设计模式与代码规范
  └── Linux / 网络基础

第三优先级（进阶）
  ├── JVM 调优、GC
  ├── 源码：Spring Boot 自动配置、Spring 事务、MyBatis
  ├── 分布式系统理论：CAP、一致性协议
  └── Kubernetes、Service Mesh
```

### 11.2.2 不要陷入的误区

- **只学中间件，不补 Java 基础**：面试第一轮就挂在 HashMap、线程池、JVM。
- **只背八股，不动手**：项目一问细节就露馅。
- **追新技术**：K8s、Service Mesh 很酷，但初级岗位更看重基础和项目。
- **收藏 100 篇博客，一篇没看完**：选定一套教程，走完它。

## 11.3 源码怎么读

### 11.3.1 不要从头读

Spring 有几百万行，从头读等于放弃。正确方式是**带着问题读**：

1. `@SpringBootApplication` 为什么能启动？
2. `@Transactional` 为什么自调用失效？
3. MyBatis 的 Mapper 接口没有实现类，为什么能调用？
4. `@Autowired` 是怎么注入的？

### 11.3.2 推荐顺序

| 主题 | 入口 | 目标 |
|---|---|---|
| Spring Boot 自动配置 | `@SpringBootApplication` → `@EnableAutoConfiguration` → `AutoConfigurationImportSelector` | 知道 `spring.factories` / `AutoConfiguration.imports` 怎么加载 |
| Bean 生命周期 | `AbstractApplicationContext.refresh()` | 知道 Bean 从创建到销毁的流程 |
| AOP 与事务 | `@EnableTransactionManagement` → `TransactionInterceptor` | 知道事务代理怎么创建、怎么回滚 |
| Spring MVC | `DispatcherServlet.doDispatch()` | 知道请求如何找到 Controller |
| MyBatis | `MapperProxy`、`MapperFactoryBean` | 知道 Mapper 接口怎么变成代理 |

### 11.3.3 读源码的方法

1. **先看官方文档和注释**，再看代码；
2. **写一个最小 demo，打断点**，跟着调用栈走；
3. **只读主流程**，跳过日志、异常分支；
4. **画时序图**，把关键类的关系画出来；
5. **写笔记**，用自己的话总结，而不是复制代码。

> 读源码的收益不是"知道每行代码"，而是"建立框架的整体心智模型"，出问题时知道去哪找。

## 11.4 Java 基础补课清单

如果你觉得基础不牢，按这个顺序补：

### 11.4.1 集合

- `ArrayList` vs `LinkedList`：底层结构、随机访问、插入删除
- `HashMap`：数组 + 链表 + 红黑树、扩容、hash 扰动、为什么线程不安全
- `ConcurrentHashMap`：分段锁 → CAS + synchronized、扩容
- `TreeMap`：红黑树、排序

### 11.4.2 并发

- 线程生命周期、`ThreadPoolExecutor` 七个参数、拒绝策略
- `synchronized` 与 `ReentrantLock` 区别
- `volatile`、`CAS`、`AQS`
- `ThreadLocal` 原理与内存泄漏
- 死锁的四个条件
- `CompletableFuture` 异步编排

### 11.4.3 JVM

- 运行时数据区：堆、栈、方法区、程序计数器
- 对象创建与内存布局
- 垃圾回收：可达性分析、分代、G1
- 类加载：双亲委派
- 常用排查工具：`jps`、`jstack`、`jmap`、`jstat`、Arthas
- 内存泄漏与 OOM 排查

### 11.4.4 网络

- TCP 三次握手、四次挥手
- HTTP/HTTPS、HTTP/2
- 常见状态码
- 跨域、Cookie/Session/Token

## 11.5 面试准备

### 11.5.1 面试的四个环节

| 环节 | 考察点 | 准备方式 |
|---|---|---|
| 基础 | Java、集合、并发、JVM | 系统复习 + 手写代码 |
| 框架 | Spring、MyBatis、Spring Boot | 理解原理，能讲流程 |
| 中间件 | MySQL、Redis、MQ、Nacos | 结合项目讲，不背孤立概念 |
| 项目 | 业务理解、难点、取舍 | 用"问题-方案-结果"准备 3 个故事 |

### 11.5.2 高频题与回答框架

**MySQL：**

- 索引为什么用 B+ 树？→ 对比二叉树/红黑树/B 树，突出"矮胖、范围查询、磁盘 IO"
- 什么情况索引失效？→ 函数运算、隐式转换、左模糊、OR、最左前缀
- RR 能解决幻读吗？→ 快照读 MVCC + 当前读 Next-Key Lock，基本解决
- 深分页怎么优化？→ 游标分页、延迟关联
- 死锁怎么排查？→ `SHOW ENGINE INNODB STATUS`、固定加锁顺序

**Redis：**

- 缓存穿透/击穿/雪崩的区别和方案？→ 分别说清"数据存不存在、key 是否热点、是否大量同时失效"
- 缓存和数据库怎么保持一致？→ Cache Aside、先更库再删缓存、延迟双删、最终一致
- 分布式锁怎么实现？→ SETNX + 过期 + 唯一 value + Lua 释放，Redisson 看门狗
- Redis 为什么快？→ 内存、单线程无锁、IO 多路复用、高效数据结构

**Kafka：**

- 为什么高吞吐？→ 顺序写、页缓存、零拷贝、批量、分区
- 怎么保证不丢消息？→ 生产 acks=all + 重试 + 幂等，存储多副本，消费手动提交
- 怎么保证不重复消费？→ 不能保证，消费者幂等 + 唯一索引
- 怎么保证顺序？→ 同一 key 进同一分区，消费端单线程处理
- 消息积压怎么办？→ 扩消费者（不超过分区）、优化消费、临时扩容分区、死信

**微服务：**

- 服务怎么拆？→ 业务能力、高内聚低耦合、数据库私有、演进式
- Nacos 注册中心原理？→ 注册、心跳、本地缓存、推送
- 服务调用超时怎么办？→ 超时、重试（幂等）、熔断、降级
- 分布式事务方案？→ 2PC/TCC/Saga/本地消息表/Seata，讲取舍
- 幂等怎么做？→ 唯一索引、状态机、Token
- 链路追踪原理？→ traceId + spanId，跨服务透传

**Spring：**

- Bean 生命周期？→ 实例化、属性注入、Aware、初始化、后置处理、销毁
- 循环依赖怎么解决？→ 三级缓存，为什么需要三级
- `@Transactional` 失效场景？→ 自调用、非 public、异常被吞、受检异常、多线程
- AOP 原理？→ 动态代理（JDK/CGLIB）

### 11.5.3 项目讲述模板

准备 3 个故事，每个 3-5 分钟：

```text
1. 背景：项目是什么，我负责什么
2. 问题：遇到了什么具体问题（有数据）
3. 方案：比较了哪些方案，为什么选这个
4. 落地：关键代码/配置/表结构
5. 结果：指标变化（P99、QPS、错误率）
6. 反思：如果重来，哪里可以做得更好
```

**示例：**

> 我们商品详情接口原来直接查 MySQL，大促时 P99 到了 800ms，数据库 CPU 打满。我对比了本地缓存、Redis、读写分离三种方案：本地缓存一致性问题大，读写分离成本高且解决不了热点，最后选 Redis + Cache Aside。针对穿透加了空值缓存，击穿用互斥锁，雪崩给 TTL 加了随机值。上线后 P99 降到 45ms，数据库 QPS 下降 90%。后来发现热点 key 集中在几个爆款，又加了本地 Caffeine 做二级缓存。如果重来，我会一开始就把缓存 key 的监控和降级预案做进去。

### 11.5.4 反问面试官

面试最后通常会让你提问，问这些能加分：

- 团队目前的技术栈和架构是怎样的？
- 新人入职后前三个月主要做什么？
- 团队怎么做出技术方案评审？有没有 code review？
- 目前系统最大的技术挑战是什么？

**不要问**：加班多不多、工资多少（HR 环节再问）、能不能远程。

## 11.6 如何在公司代码里成长

### 11.6.1 第一周

1. 把项目跑起来，跑通一个完整业务；
2. 看 `pom.xml`、配置文件、启动类；
3. 画一张自己理解的架构图，找导师确认；
4. 找一个最简单的需求，从头到尾跟一遍：需求 → 设计 → 开发 → 测试 → 上线。

### 11.6.2 第一个月

1. 主动接小需求，不要只改 bug；
2. 每次提交前看一遍 diff，学习团队的代码风格；
3. 遇到问题先自己查 30 分钟，再问人，问的时候带上"我试了什么、报错是什么"；
4. 记录踩过的坑，形成自己的知识库。

### 11.6.3 第三个月

1. 能独立负责一个模块；
2. 开始关注非功能需求：性能、异常、监控、告警；
3. 参与 code review，学习别人怎么指出问题；
4. 尝试优化一个小的技术点，用数据证明效果。

### 11.6.4 看代码的技巧

- **从入口往下看**：Controller → Service → Mapper；
- **从日志反推**：找一条错误日志，顺着 traceId 看调用链；
- **从表结构理解业务**：表名、字段、索引能反映业务模型；
- **看 Git 历史**：`git log -p` 看某个文件为什么这么改；
- **看测试用例**：测试是最好的文档。

## 11.9 技术方向怎么选

工作 2-3 年后，可以往这些方向深入：

| 方向 | 核心能力 | 适合 |
|---|---|---|
| **业务后端** | 领域建模、复杂业务、稳定性 | 大多数后端 |
| **基础架构** | 中间件、框架、RPC、存储 | 喜欢底层、造轮子 |
| **大数据** | Flink、Spark、数仓 | 数据量大、分析场景 |
| **云原生** | K8s、Service Mesh、Operator | 基础设施团队 |
| **架构师** | 技术选型、系统设计、团队协作 | 沟通 + 技术都强 |

> 不要过早锁定方向。先把后端主干做深，再根据兴趣和机会选择。

## 11.10 最后的话

你现在的状态，不是"什么都不会"，而是"会了零件，还没装成机器"。这套教程做的就是"装机器"的事。

三个建议：

1. **不要追求学完所有技术再开始**。技术永远学不完，边做边学才是常态。
2. **每个技术都问"为什么"**。为什么需要它？不用会怎样？用了会引入什么新问题？
3. **保持输出**。写笔记、写博客、做分享，能讲清楚才是真的会。

公司里那些看起来很厉害的后端，并不是记住了所有 API，而是：

- 遇到问题知道**去哪找**；
- 做方案知道**怎么取舍**；
- 出了故障知道**怎么定位**。

这些能力，只能通过一个个项目、一次次踩坑积累。现在开始，就不晚。

## 11.11 本章小结

1. **先盘点，再补短板**；不要盲目追新技术。
2. **源码带着问题读**，先主流程，后细节，画图总结。
3. **面试=基础+框架+中间件+项目**，项目用"问题-方案-结果"讲。
4. **在公司里主动接需求、看 diff、记笔记、做分享**，成长最快。
5. **90 天计划**：前 30 天打基础，中间 30 天做项目补基础，最后 30 天面试冲刺。
