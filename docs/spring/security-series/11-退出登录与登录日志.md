## 11.2 无状态 Token 的失效难题

JWT 签发后，在过期之前天然有效。服务端不存 Token，所以默认**无法主动让它失效**。

三种常见方案：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| `tokenVersion` | 用户表存版本号，退出时 +1；Token 里也带版本号，比对不上就拒绝 | 不引入额外组件，实现简单 | 只能“全端下线”，不能让单个设备失效 |
| Redis 黑名单 | 退出时把 Token 的 `jti` 写入 Redis，过期时间与 Token 一致 | 可精确让单个 Token 失效 | 引入 Redis 依赖 |
| 短 TTL + Refresh Token | Access Token 只有几分钟，Refresh Token 存服务端 | 安全性高 | 实现复杂，前端要处理刷新 |

本系列选 `tokenVersion`，因为不引入 Redis，而且足够让你理解“无状态 Token 怎么主动失效”。

### 11.3.4 Service 实现

`src/main/java/com/keywin/security/modules/log/service/impl/SysLoginLogServiceImpl.java`：

```java
package com.keywin.security.modules.log.service.impl;

import com.keywin.security.modules.log.entity.SysLoginLog;
import com.keywin.security.modules.log.mapper.SysLoginLogMapper;
import com.keywin.security.modules.log.service.SysLoginLogService;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class SysLoginLogServiceImpl implements SysLoginLogService {

    private static final int MAX_LENGTH = 255;

    private final SysLoginLogMapper sysLoginLogMapper;

    @Override
    public void record(Long userId,
                       String username,
                       String ip,
                       String userAgent,
                       boolean success,
                       String message) {
        SysLoginLog log = new SysLoginLog();
        log.setUserId(userId);
        log.setUsername(username);
        log.setIp(ip);
        log.setUserAgent(truncate(userAgent));
        log.setSuccess(success ? 1 : 0);
        log.setMessage(truncate(message));
        sysLoginLogMapper.insert(log);
    }

    /**
     * 数据库字段是 VARCHAR(255)，超长会报 Data truncation。
     */
    private String truncate(String value) {
        if (value == null || value.length() <= MAX_LENGTH) {
            return value;
        }
        return value.substring(0, MAX_LENGTH);
    }
}
```

## 11.4 修改 SysUserMapper：更新登录信息和版本号

`src/main/java/com/keywin/security/modules/user/mapper/SysUserMapper.java` **完整替换为**：

```java
package com.keywin.security.modules.user.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.keywin.security.modules.user.entity.SysUser;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Update;

import java.time.LocalDateTime;

@Mapper
public interface SysUserMapper extends BaseMapper<SysUser> {

    /**
     * 登录成功后更新最后登录时间和 IP。
     */
    @Update("""
            UPDATE sys_user
            SET last_login_time = #{loginTime}, last_login_ip = #{ip}
            WHERE id = #{userId}
            """)
    int updateLoginInfo(@Param("userId") Long userId,
                        @Param("loginTime") LocalDateTime loginTime,
                        @Param("ip") String ip);

    /**
     * 退出登录：令牌版本 +1，让该用户所有旧 Token 失效。
     */
    @Update("UPDATE sys_user SET token_version = token_version + 1 WHERE id = #{userId}")
    int incrementTokenVersion(@Param("userId") Long userId);
}
```

为什么要用 `@Update` 而不是 `updateById`？

- 只更新需要的字段，不会把整个实体写回去。
- 避免并发更新时覆盖其他字段。
- `token_version = token_version + 1` 是数据库原子操作，不会丢更新。

## 11.6 修改 AuthServiceImpl

`src/main/java/com/keywin/security/modules/auth/service/impl/AuthServiceImpl.java` **完整替换为**：

```java
package com.keywin.security.modules.auth.service.impl;

import com.keywin.security.modules.auth.dto.AuthLoginDTO;
import com.keywin.security.modules.auth.service.AuthService;
import com.keywin.security.modules.auth.vo.AuthLoginVO;
import com.keywin.security.modules.log.service.SysLoginLogService;
import com.keywin.security.modules.user.mapper.SysUserMapper;
import com.keywin.security.security.JwtService;
import com.keywin.security.security.LoginUser;
import jakarta.servlet.http.HttpServletRequest;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.AuthenticationException;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

import java.time.LocalDateTime;

@Slf4j
@Service
@RequiredArgsConstructor
public class AuthServiceImpl implements AuthService {

    private final AuthenticationManager authenticationManager;
    private final JwtService jwtService;
    private final SysUserMapper sysUserMapper;
    private final SysLoginLogService sysLoginLogService;

    @Override
    public AuthLoginVO login(AuthLoginDTO dto, HttpServletRequest request) {
        String ip = getClientIp(request);
        String userAgent = request.getHeader("User-Agent");

        Authentication authentication;
        try {
            authentication = authenticationManager.authenticate(
                    new UsernamePasswordAuthenticationToken(
                            dto.getUsername(), dto.getPassword())
            );
        } catch (AuthenticationException e) {
            // 登录失败也要记录，方便排查撞库、暴力破解
            sysLoginLogService.record(
                    null, dto.getUsername(), ip, userAgent, false, e.getMessage());
            throw e;
        }

        LoginUser loginUser = (LoginUser) authentication.getPrincipal();

        // 更新最后登录信息
        sysUserMapper.updateLoginInfo(loginUser.getUserId(), LocalDateTime.now(), ip);

        // 记录成功日志
        sysLoginLogService.record(
                loginUser.getUserId(), loginUser.getUsername(),
                ip, userAgent, true, null);

        AuthLoginVO vo = new AuthLoginVO();
        fillUserInfo(vo, loginUser);
        vo.setToken(jwtService.generateToken(loginUser));
        vo.setTokenType("Bearer");
        vo.setExpiresIn(jwtService.getExpirationSeconds());
        return vo;
    }

    @Override
    public void logout(LoginUser loginUser) {
        sysUserMapper.incrementTokenVersion(loginUser.getUserId());
        log.info("用户退出登录: id={}, username={}",
                loginUser.getUserId(), loginUser.getUsername());
    }

    @Override
    public AuthLoginVO me(LoginUser loginUser) {
        AuthLoginVO vo = new AuthLoginVO();
        fillUserInfo(vo, loginUser);
        return vo;
    }

    private void fillUserInfo(AuthLoginVO vo, LoginUser loginUser) {
        vo.setUserId(loginUser.getUserId());
        vo.setUsername(loginUser.getUsername());
        vo.setNickname(loginUser.getNickname());
        vo.setRoles(loginUser.getRoles());
        vo.setPermissions(loginUser.getPermissions());
    }

    /**
     * 取客户端 IP。优先代理头，其次 remoteAddr。
     * 数据库字段是 VARCHAR(64)，这里截断，避免恶意超长头导致插入失败。
     */
    private String getClientIp(HttpServletRequest request) {
        String ip = resolveClientIp(request);
        if (ip == null) {
            return "unknown";
        }
        return ip.length() > 64 ? ip.substring(0, 64) : ip;
    }

    private String resolveClientIp(HttpServletRequest request) {
        String xForwardedFor = request.getHeader("X-Forwarded-For");
        if (StringUtils.hasText(xForwardedFor)
                && !"unknown".equalsIgnoreCase(xForwardedFor)) {
            return xForwardedFor.split(",")[0].trim();
        }

        String xRealIp = request.getHeader("X-Real-IP");
        if (StringUtils.hasText(xRealIp)
                && !"unknown".equalsIgnoreCase(xRealIp)) {
            return xRealIp;
        }

        return request.getRemoteAddr();
    }
}
```

### 说明

- 登录失败时 `userId` 传 null：`AuthenticationException` 不携带用户 ID。用户名不存在时本来也没有 ID；密码错误时如果想记 ID，可以再查一次数据库，但没必要。
- `e.getMessage()` 可能是 `Bad credentials`，会写进 `message` 字段。
- 只有登录成功才更新 `last_login_time` / `last_login_ip`。
- 退出登录只做一件事：`token_version + 1`。

package com.keywin.security.modules.auth.controller;

import com.keywin.security.common.api.Result;
import com.keywin.security.modules.auth.dto.AuthLoginDTO;
import com.keywin.security.modules.auth.service.AuthService;
import com.keywin.security.modules.auth.vo.AuthLoginVO;
import com.keywin.security.security.LoginUser;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.security.core.annotation.AuthenticationPrincipal;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/auth")
@RequiredArgsConstructor
public class AuthController {

    private final AuthService authService;

    @PostMapping("/login")
    public Result<AuthLoginVO> login(@Valid @RequestBody AuthLoginDTO dto,
                                     HttpServletRequest request) {
        return Result.success(authService.login(dto, request));
    }

    @PostMapping("/logout")
    public Result<Void> logout(@AuthenticationPrincipal LoginUser loginUser) {
        authService.logout(loginUser);
        return Result.success();
    }

    @GetMapping("/me")
    public Result<AuthLoginVO> me(@AuthenticationPrincipal LoginUser loginUser) {
        return Result.success(authService.me(loginUser));
    }
}

## 11.8 过滤器的版本校验（第 07 章已经写了）

`JwtAuthenticationFilter` 里有这段：

```java
if (userDetails instanceof LoginUser loginUser
        && loginUser.getUserId().equals(userId)
        && loginUser.getTokenVersion().equals(tokenVersion)
        && loginUser.isEnabled()) {
    // 设置认证
}
```

退出登录后：

1. 数据库 `token_version` 从 0 变成 1。
2. 旧 Token 里的 `tokenVersion` 还是 0。
3. 过滤器加载 `LoginUser`，发现 `0 != 1`。
4. 不设置认证。
5. `AuthorizationFilter` 判定未认证。
6. `ExceptionTranslationFilter` 调用 `EntryPoint` → 401。

不需要改过滤器。如果你在第 07 章漏了版本校验，现在补上。

## 11.10 常见报错

### 1. 退出后旧 Token 还能用

原因：

- `tokenVersion` 没有在过滤器里比对
- 或者 `incrementTokenVersion` 没执行

排查：

```sql
SELECT username, token_version FROM sys_user WHERE username = 'admin';
```

退出前后对比，版本号应该 +1。

### 2. 登录日志没写

原因：

- 登录失败时，异常在写日志之前抛出
- 日志表字段长度不够，插入失败
- `SysLoginLogService` 没有被注入

解决：

- 确认 `try/catch` 包住了 `authenticate`。
- 确认 `userAgent`、`message` 截断到 255。
- 看控制台有没有 SQL 异常。

### 3. `last_login_time` 不更新

原因：`updateLoginInfo` 没调用，或者 SQL 条件不对。

解决：确认登录成功后调用了 `sysUserMapper.updateLoginInfo(...)`。

### 4. 退出登录返回 401

原因：`/api/auth/logout` 需要认证，但请求没带 Token。

解决：带上 `Authorization: Bearer <token>`。

### 5. 日志插入报 `Data truncation`

原因：`User-Agent` 超过 255 字符。

解决：`SysLoginLogServiceImpl` 里已经 `truncate`；如果还报，检查是不是 `message` 超长。

### 6. 版本号变成 null

原因：数据库 `token_version` 允许 null，或者插入用户时没设置。

解决：建表时 `NOT NULL DEFAULT 0`；创建用户时 `setTokenVersion(0)`。

### 7. 退出两次，第二次 401

这是正常的。第一次退出后 Token 已失效，第二次请求在过滤器就被拒绝，根本进不了 Controller。

## 11.11 安全说明

`tokenVersion` 的失效范围是**整个用户**：

- 用户在手机、电脑、平板同时登录。
- 在手机上退出，所有设备的 Token 都会失效。

这适合“改密码后强制所有设备重新登录”，但不适合“只让当前设备退出”。

要做单设备退出，需要：

- 每个 Token 一个唯一 `jti`
- 退出时把 `jti` 写入 Redis 黑名单
- 过滤器检查黑名单

这是第 13 章“下一步”的内容。

## 11.12 本章小结

- `tokenVersion` 解决无状态 Token 的主动失效。
- 退出登录：`token_version + 1`。
- 过滤器每次比对 Token 里的版本和数据库版本。
- 登录成功更新 `last_login_time` / `last_login_ip`。
- 登录成功/失败都写 `sys_login_log`，失败记录便于排查暴力破解。
- `tokenVersion` 是全端下线，不是单设备下线。

### 自测题

1. 为什么 JWT 默认无法主动失效？
2. `tokenVersion` 方案为什么能失效旧 Token？
3. 登录失败时为什么也要写日志？
4. 退出登录后，旧 Token 是在哪一步被拒绝的？
5. 如果要让单个设备退出，应该怎么做？

<details>
<summary>参考答案</summary>

1. 服务端不存 Token，只验证签名和过期时间，签发后到期前一直有效。
2. 退出时数据库版本 +1，旧 Token 里的版本号对不上，过滤器不设置认证。
3. 便于发现撞库、暴力破解、异常 IP 登录；也是安全审计的基本要求。
4. `JwtAuthenticationFilter` 比对 `tokenVersion` 失败 → 不设置认证 → `AuthorizationFilter` 拒绝 → `EntryPoint` 返回 401。
5. 给每个 Token 一个 `jti`，退出时写入 Redis 黑名单，过滤器检查黑名单。

</details>
