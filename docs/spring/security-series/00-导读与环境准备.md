# 第 00 章 导读与环境准备

> 本章不写代码。你要做的是：把环境检查一遍、把数据库建好、知道接下来 13 章怎么走。

---

## 0.1 这套教程怎么用

### 每章的固定结构

```text
本章目标       → 这一章做完，你能验证的一个具体结果
前置检查       → 上一章的东西是否还在，不通过就别往下走
先跑通         → 完整目录树 + 每个文件的完整代码
再解释         → 逐行讲清楚“为什么必须这么写”
验证           → curl / HTTP 请求 + 预期响应
常见报错       → 你大概率会遇到的坑
小结 + 自测题   → 确认自己真的会了
```

### 三条学习规则

1. **按顺序读。** 第 07 章的 `JwtAuthenticationFilter` 依赖第 05 章的 `LoginUser`、第 06 章的 `JwtService`。跳章一定编译不过。
2. **代码自己敲。** 每章都给完整文件（含 `package` 和全部 `import`），可以复制，但关键类建议手敲一遍。
3. **验证不通过，不往下走。** 每章结束都是一个可运行状态。带着上一章的错误往下写，后面会同时出现三四个问题，很难定位。

### 不要做的事

- 不要一次性把 14 章代码全写完再启动。
- 不要同时改多个层（Controller + Service + Security 配置）然后一起调试。
- 不要把网上 0.11.x jjwt 或 Spring Security 5 的代码片段混进来。

## 0.2 你会做出什么

最终你会得到一个 `security-lab` 工程，具备：

| 能力 | 你会看到的结果 |
| --- | --- |
| 登录 | `POST /api/auth/login` 返回 JWT |
| 每请求认证 | 带 `Authorization: Bearer <token>` 能访问受保护接口 |
| 用户 CRUD | 分页、详情、新增、修改、删除 |
| 角色 CRUD | 角色的增删改查 |
| 权限 CRUD | 权限的增删改查 |
| 分配角色 | 给用户分配多个角色 |
| 分配权限 | 给角色分配多个权限 |
| URL 级授权 | 不同角色访问同一路径得到 200 / 403 |
| 方法级授权 | `@PreAuthorize` 控制到具体方法 |
| 401 / 403 | 未登录 401，没权限 403，都是 JSON |
| 退出失效 | 退出后旧 Token 立即 401 |
| 登录日志 | 成功/失败都写 `sys_login_log` |
| 测试 | `mvn test` 覆盖认证和授权 |

三个账号的能力边界：

| 账号 | 密码 | 角色 | 能做什么 |
| --- | --- | --- | --- |
| `admin` | `admin123` | `SUPER_ADMIN` | 全部 |
| `user_admin` | `user123` | `USER_ADMIN` | 用户查询/新增/修改；角色、权限只读 |
| `viewer` | `viewer123` | `VIEWER` | 用户、角色、权限都只读 |

## 0.3 学习地图

```text
阶段一：把工程和安全框架跑起来
  01 工程搭建与数据库
  02 Security 初体验与过滤器链
        ↓

  04 角色与权限模块 CRUD

  06 JWT 生成与解析
  07 JwtAuthenticationFilter 与 401
  08 URL 级授权与 403
        ↓
阶段四：细粒度权限与收尾
  09 方法级授权
  10 分配角色与分配权限
```

**最重要的里程碑是第 05 章**：登录能跑通。第 06~08 章只是在登录成功的基础上加 Token 和授权。第 05 章卡住，不要往后走。

## 0.5 数据库准备

### 方式一：命令行

在 `docs/spring/security-series` 目录下执行：

```bash
mysql -u root -p < sql/01-schema.sql
mysql -u root -p < sql/02-data.sql
```

输入 MySQL 密码后，两个文件都不应该报错。

### 方式二：IDEA Database

1. 右侧 Database → `+` → Data Source → MySQL
2. Host `localhost`，Port `3306`，User `root`，输入密码
3. 打开 `sql/01-schema.sql`，选中全部，点绿色三角执行
4. 再打开 `sql/02-data.sql`，同样执行

### 验证数据

执行：

```sql
USE security_lab;

SELECT id, username, nickname, status, token_version FROM sys_user;
SELECT COUNT(*) AS role_count FROM sys_role;
SELECT COUNT(*) AS permission_count FROM sys_permission;
SELECT COUNT(*) AS user_role_count FROM sys_user_role;
SELECT COUNT(*) AS role_permission_count FROM sys_role_permission;
```

预期：

```text
3 行用户：admin、user_admin、viewer
role_count = 3
permission_count = 12
user_role_count = 3
role_permission_count = 20
```

如果数量不对，重新执行 `02-data.sql`（它会先清空再插入）。

## 0.7 遇到问题怎么排查

按这个顺序，不要一上来就改代码：

1. **应用起来了吗？**
   ```bash
   curl http://localhost:8080/api/ping
   ```
   第 01 章之后，这个接口应该返回 `{"status":"ok"}`（第 02 章会被 Security 拦成 401，这是正常的，第 03 章恢复）。

2. **控制台第一条异常是什么？**
   从下往上看堆栈没用，第一条 `Caused by` 才是根因。

3. **打开 Security 调试日志。**
   在 `application.yml` 加：
   ```yaml
   logging:
     level:
       org.springframework.security: DEBUG
   ```
   重启后能看到请求经过了哪些过滤器、授权决策是什么。

4. **确认数据库连接。**
   启动日志里应该有 `HikariPool-1 - Start completed`。没有就是数据源配置或 MySQL 没启动。

5. **确认 SQL 执行过。**
   `SELECT COUNT(*) FROM sys_user;` 返回 3，而不是表不存在。
