## 13.3 Security 知识地图

```text
认证（你是谁）
├── PasswordEncoder              密码加密与比对
├── UserDetailsService           按用户名查用户
├── UserDetails / LoginUser      用户模型 + 权限集合
├── AuthenticationManager        认证调度器
├── Authentication               认证结果（principal + authorities）
└── DaoAuthenticationProvider    查用户 + 验密码的具体实现

授权（你能做什么）
├── SecurityFilterChain          URL 级规则
├── AuthorizationFilter          执行 URL 规则
├── @EnableMethodSecurity        开启方法级
├── @PreAuthorize                方法级规则
└── GrantedAuthority             权限字符串

上下文（当前用户）
├── SecurityContextHolder        ThreadLocal 容器
├── SecurityContext              当前请求的安全上下文
└── @AuthenticationPrincipal     从上下文取 principal

异常（怎么响应）
├── AuthenticationEntryPoint     未认证 -> 401
├── AccessDeniedHandler          无权限 -> 403
├── AuthenticationException      认证失败
└── AccessDeniedException        授权失败

JWT
├── JwtService                   生成 / 解析
├── JwtAuthenticationFilter      每请求认证
└── tokenVersion                 主动失效
```

## 13.4 常见坑清单（20 条）

| # | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 1 | 加依赖后所有接口 401 | 默认链拦截全部 | 写 `SecurityFilterChain` |
| 2 | 登录永远失败 | 数据库存明文密码 | 用 BCrypt 重新编码 |
| 3 | `There is no PasswordEncoder mapped for the id "null"` | 没配 `PasswordEncoder` Bean，或哈希不是 BCrypt | 第 05 章 |
| 4 | 配置了 `permitAll` 还是 401 | 自定义过滤器抛异常中断请求 | 过滤器内 try-catch，继续放行 |
| 5 | 有权限却 403 | `hasRole("ADMIN")` 但 authorities 里没有 `ROLE_ADMIN` | 统一前缀 |
| 6 | 401/403 返回 HTML | 没配 `EntryPoint` / `AccessDeniedHandler` | 第 07、08 章 |
| 7 | 异步/线程池里拿不到用户 | `SecurityContextHolder` 是 ThreadLocal | `DelegatingSecurityContextRunnable` |
| 8 | 跨域报错且带 `allowCredentials(true)` | 用了 `allowedOrigins("*")` | 改 `allowedOriginPatterns("*")` |
| 9 | Swagger/Knife4j 打不开 | 路径被拦截 | 加入 `permitAll` 白名单 |
| 10 | Boot 3 编译不过 | 还在用 `WebSecurityConfigurerAdapter` / `antMatchers` | `SecurityFilterChain` / `requestMatchers` |
| 11 | jjwt 编译报错 | 0.12.x 依赖抄了 0.11.x API | 第 06 章对照表 |
| 12 | Token 有效却认证不上 | 过滤器某个分支没 `chain.doFilter` | 所有分支都要放行 |
| 13 | 退出后 Token 还能用 | 过滤器没校验 `tokenVersion` | 第 11 章 |
| 14 | `matches` 永远 false | 参数传反 | `matches(明文, 密文)` |
| 15 | `@PreAuthorize` 不生效 | 没加 `@EnableMethodSecurity` | 第 09 章 |
| 16 | `hasRole("ROLE_ADMIN")` 永远 403 | 双前缀 | `hasRole("ADMIN")` |
| 17 | `WeakKeyException` | secret 少于 32 字节 | 换长密钥 |
| 18 | 改权限后旧 Token 不生效 | 权限被放进 JWT | 权限从数据库加载 |
| 19 | 过滤器执行两次 | 过滤器加了 `@Component` | 配置类里手动 `new` |
| 20 | `@WithMockUser` 测试 500 | principal 不是 `LoginUser` | 用不需要 principal 的端点或真实 Token |
| 21 | 具体路径规则不生效 | `anyRequest()` 写在前面 | 具体规则在前，`anyRequest()` 最后 |
| 22 | `@Transactional` 不生效 | 同类内部 `this.xxx()` 调用 | 从 Controller 调 Service 接口 |
| 23 | 登录日志 `Data truncation` | User-Agent / message 超长 | 截断到 255 |
| 24 | 改密码后旧 Token 还能用 | 没有递增 `tokenVersion` | 修改密码时 +1 |
| 25 | 已有认证被覆盖 | 没判断 `getAuthentication() == null` | 过滤器里先判断 |

## 13.5 迁回 `mall-product` 对照表

你现有的 `mall-product` 是手写版。迁移时逐个对照：

| `mall-product` 旧写法 | `security-lab` 新写法 | 说明 |
| --- | --- | --- |
| `JwtAuthInterceptor` | `JwtAuthenticationFilter` | 拦截器变过滤器 |
| `WebMvcConfig.addInterceptors(...)` | `SecurityConfig.addFilterBefore(...)` | 不再手动注册拦截器 |
| `UserContextHolder`（ThreadLocal） | `SecurityContextHolder` | 框架自带上下文 |
| `UserContext` record | `LoginUser implements UserDetails` | 用户模型 |
| `@RequirePermission` | `@PreAuthorize` | 注解替换 |
| `PermissionAspect`（AOP） | 删除 | 框架已实现 |
| `ForbiddenException` | `AccessDeniedException` / `AccessDeniedHandler` | 403 |
| `UnauthorizedException` | `AuthenticationEntryPoint` | 401 |
| `JwtTokenProvider` | `JwtService` | 生成/解析 |
| `AuthServiceImpl.login` 手动查用户 + `matches` | `AuthenticationManager.authenticate` | 认证交给框架 |
| `AuthServiceImpl.logout` 的 `tokenVersion + 1` | 保留 | 思路一致 |
| `PasswordConfig` | 保留 | BCrypt |
| `Result` / `ResultCode` | 保留 | 响应格式 |
| `GlobalExceptionHandler` | 增加 `AuthenticationException` / `AccessDeniedException` | 统一 JSON |
| `AdminAuthController` | `AuthController` | 路径可保持不变 |
| `SysUser` / `SysRole` / `SysPermission` | 保留 | 实体可复用 |
| `SysUserMapper` / `SysRoleMapper` / `SysPermissionMapper` | 保留，补 RBAC 查询 | 见第 05 章 |
| `AdminLoginVO` | `AuthLoginVO` | 加 token 字段 |
| `UserContextHolder.getUserContext()` | `@AuthenticationPrincipal LoginUser` | 业务代码取值 |

### 迁移顺序（建议）

1. **加依赖，先别删旧代码**：加 `spring-boot-starter-security`，写一个 `SecurityConfig` 暂时 `permitAll()`，确认应用能启动。
2. **补 `LoginUser` 和 `UserDetailsService`**：复用现有 `SysUser`、角色、权限查询。
3. **改登录接口**：从手动查库 + `matches` 改成 `AuthenticationManager`，先不返回 JWT，确认登录成功。
4. **接 `JwtService`**：登录返回 Token，保持旧 `JwtTokenProvider` 暂时不动，对比两者 Claims。
5. **接 `JwtAuthenticationFilter`**：把旧 `JwtAuthInterceptor` 从 `WebMvcConfig` 摘掉，避免两套认证同时跑。
6. **接 401/403**：`RestAuthenticationEntryPoint` + `RestAccessDeniedHandler`。
7. **替换权限注解**：`@RequirePermission` → `@PreAuthorize`，删除 `PermissionAspect`。
8. **清理**：删除 `UserContextHolder`、`UserContext`、旧拦截器、旧 AOP。
9. **回归测试**：用第 12 章的测试思路覆盖登录、401、403、退出。

### 数据迁移

如果 `mall-product` 的 `sys_user.password_hash` 已经是 BCrypt，直接复用。

如果是明文：

- 学习环境：重新执行种子 SQL，用 BCrypt 哈希覆盖。
- 生产环境：登录成功时判断旧格式，`encode` 后写回（渐进升级），或者强制重置密码。

## 13.6 自测题（10 题）

1. 一个请求进入 Spring Security，最先经过哪两个组件？
2. `UserDetailsService` 和 `UserDetails` 分别负责什么？
3. `AuthenticationManager` 内部是谁在查用户、谁在比密码？
4. 401 和 403 分别由哪个组件产生？
5. 为什么本系列不把角色/权限放进 JWT？
6. `tokenVersion` 是怎么让旧 Token 失效的？
7. 方法级 `@PreAuthorize` 抛出的 403 为什么走 `@RestControllerAdvice`？
8. `hasRole("ADMIN")` 和 `hasAuthority("admin")` 分别匹配什么？
9. 为什么 `JwtAuthenticationFilter` 不加 `@Component`？
10. 为什么改完角色后，旧 Token 不需要重新登录就能生效？

<details>
<summary>参考答案</summary>

1. `DelegatingFilterProxy` → `FilterChainProxy`，再由 `FilterChainProxy` 找到 `SecurityFilterChain`。
2. `UserDetailsService` 负责“怎么查用户”；`UserDetails` 是查出来的“用户模型”（用户名、密码、权限、状态）。
3. `DaoAuthenticationProvider` 调用 `UserDetailsService` 查用户，调用 `PasswordEncoder.matches` 比密码。
4. 401 → `AuthenticationEntryPoint`；403 → `AccessDeniedHandler`（方法级 403 走 `@RestControllerAdvice`）。
5. 权限放进 JWT 后，权限变更旧 Token 不会更新；放数据库每次加载才能立即生效。
6. 退出登录时数据库 `token_version + 1`；过滤器比对 Token 里的版本和数据库版本，不一致就不认证。
7. 它发生在 DispatcherServlet 调用 Controller 方法时，属于 MVC 调用栈，能被 `@RestControllerAdvice` 捕获。
8. `hasRole("ADMIN")` 匹配 `ROLE_ADMIN`；`hasAuthority("admin")` 精确匹配 `admin`，不补前缀。
9. 避免 Spring Boot 把它自动注册成 Servlet 过滤器，导致重复执行或执行顺序错误。
10. 过滤器每次请求都从数据库重新加载角色和权限，不依赖 JWT 里的权限。

</details>

## 13.7 下一步学什么

你已经掌握了 Spring Security 的核心闭环。接下来按需学习：

| 主题 | 解决什么问题 | 建议 |
| --- | --- | --- |
| Refresh Token | Access Token 太短，频繁登录 | 短期 Access + 长期 Refresh，Refresh 存服务端 |
| Redis 黑名单 / `jti` | 单设备退出、精确失效 | 每个 Token 一个 `jti`，退出写 Redis |
| 菜单/按钮权限树 | 前端动态菜单 | 权限表加 `parent_id`、`type`，返回树 |
| 数据权限 | 只能看自己部门的数据 | MyBatis 拦截器 / 注解 + SQL 拼接 |
| 权限缓存 | 每请求两次 DB 查询 | Redis / Caffeine + 权限变更时失效 |
| OAuth2 / 单点登录 | 第三方登录、统一认证 | `spring-boot-starter-oauth2-client` |
| 限流与审计 | 防暴力破解、操作留痕 | Redis 计数、登录日志、操作日志 |
| 异步上下文传递 | 线程池里拿不到当前用户 | `DelegatingSecurityContextRunnable` |
| CORS / Swagger 放行 | 前端联调、接口文档 | `CorsConfigurationSource` + `permitAll` 白名单 |

不要一次性全学。用到哪个再补哪个。

## 13.8 一句话总结

> **Spring Security = 一条过滤器链 + 一个 `SecurityContext` + 一组授权规则。**

你要写的只有四件事：

1. **查用户**：`UserDetailsService`
2. **比密码**：`PasswordEncoder`
3. **把 Token 解析成当前用户**：`JwtAuthenticationFilter`
4. **声明谁能访问什么**：`SecurityFilterChain` + `@PreAuthorize`

剩下的拦截、上下文保存、权限判断、401/403，框架全包了。
