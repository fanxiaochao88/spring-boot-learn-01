# 第 08 章 URL 级授权与 403

> 本章目标：三个账号访问同一批接口，得到明确的 200 / 403 矩阵。
> 未登录是 401，已登录但没权限是 403，两者都是 JSON。

---

## 8.1 前置检查

第 07 章完成：

```bash
curl -i http://localhost:8080/api/auth/me
```

不带 Token 应该是 401 JSON；带 admin Token 应该是 200。如果还是 401 或 500，先回第 07 章排查。

## 8.2 401 和 403 不是一回事

| 状态码 | 含义 | 触发场景 | 处理组件 |
| --- | --- | --- | --- |
| **401 Unauthorized** | 我不知道你是谁 | 没带 Token、Token 过期、Token 非法 | `AuthenticationEntryPoint` |
| **403 Forbidden** | 我知道你是谁，但你没资格 | 普通用户访问管理员接口、缺少权限 | `AccessDeniedHandler` |

前端处理方式完全不同：

- 401：清空本地 Token，跳登录页。
- 403：弹“权限不足”，不要跳登录页。

新手最常犯的错：把 401 和 403 混用，前端无法区分“请去登录”和“你没权限”。

## 8.3 先跑通：RestAccessDeniedHandler

`src/main/java/com/keywin/security/security/RestAccessDeniedHandler.java`：

```java
package com.keywin.security.security;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.keywin.security.common.api.Result;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.security.access.AccessDeniedException;
import org.springframework.security.web.access.AccessDeniedHandler;
import org.springframework.stereotype.Component;

import java.io.IOException;

@Component
@RequiredArgsConstructor
public class RestAccessDeniedHandler implements AccessDeniedHandler {

    private final ObjectMapper objectMapper;

    @Override
    public void handle(HttpServletRequest request,
                       HttpServletResponse response,
                       AccessDeniedException accessDeniedException) throws IOException {
        response.setStatus(HttpServletResponse.SC_FORBIDDEN);
        response.setContentType("application/json;charset=UTF-8");
        objectMapper.writeValue(
                response.getWriter(),
                Result.error(403, "权限不足，禁止访问")
        );
    }
}
```

和第 07 章的 `RestAuthenticationEntryPoint` 对称：

- `AuthenticationEntryPoint` 管“没登录” → 401
- `AccessDeniedHandler` 管“登录了但没权限” → 403

## 8.5 修改 SecurityConfig：URL 规则

`src/main/java/com/keywin/security/config/SecurityConfig.java` **完整替换为**：

```java
package com.keywin.security.config;

import com.keywin.security.security.JwtAuthenticationFilter;
import com.keywin.security.security.JwtService;
import com.keywin.security.security.RestAccessDeniedHandler;
import com.keywin.security.security.RestAuthenticationEntryPoint;
import lombok.RequiredArgsConstructor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;
    private final RestAuthenticationEntryPoint authenticationEntryPoint;
    private final RestAccessDeniedHandler accessDeniedHandler;

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        JwtAuthenticationFilter jwtAuthenticationFilter =
                new JwtAuthenticationFilter(jwtService, userDetailsService);

        http
                .csrf(AbstractHttpConfigurer::disable)
                .sessionManagement(session ->
                        session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))

                .authorizeHttpRequests(auth -> auth
                        // ① 公开路径
                        .requestMatchers(
                                "/api/auth/login",
                                "/api/ping",
                                "/api/demo/public"
                        ).permitAll()

                        // ② 管理员路径：需要 ROLE_SUPER_ADMIN
                        .requestMatchers("/api/admin/**").hasRole("SUPER_ADMIN")

                        // ③ 用户模块：按 HTTP 方法细分权限
                        .requestMatchers(HttpMethod.GET,
                                "/api/users", "/api/users/**").hasAuthority("user:list")
                        .requestMatchers(HttpMethod.POST,
                                "/api/users", "/api/users/**").hasAuthority("user:add")
                        .requestMatchers(HttpMethod.PUT,
                                "/api/users", "/api/users/**").hasAuthority("user:update")
                        .requestMatchers(HttpMethod.DELETE,
                                "/api/users", "/api/users/**").hasAuthority("user:delete")

                        // ④ 角色模块
                        .requestMatchers(HttpMethod.GET,
                                "/api/roles", "/api/roles/**").hasAuthority("role:list")
                        .requestMatchers(HttpMethod.POST,
                                "/api/roles", "/api/roles/**").hasAuthority("role:add")
                        .requestMatchers(HttpMethod.PUT,
                                "/api/roles", "/api/roles/**").hasAuthority("role:update")
                        .requestMatchers(HttpMethod.DELETE,
                                "/api/roles", "/api/roles/**").hasAuthority("role:delete")

                        // ⑤ 权限模块
                        .requestMatchers(HttpMethod.GET,
                                "/api/permissions", "/api/permissions/**").hasAuthority("permission:list")
                        .requestMatchers(HttpMethod.POST,
                                "/api/permissions", "/api/permissions/**").hasAuthority("permission:add")
                        .requestMatchers(HttpMethod.PUT,
                                "/api/permissions", "/api/permissions/**").hasAuthority("permission:update")
                        .requestMatchers(HttpMethod.DELETE,
                                "/api/permissions", "/api/permissions/**").hasAuthority("permission:delete")

                        // ⑥ 其他接口：登录即可
                        .anyRequest().authenticated())

                .exceptionHandling(ex -> ex
                        .authenticationEntryPoint(authenticationEntryPoint)
                        .accessDeniedHandler(accessDeniedHandler))

                .addFilterBefore(jwtAuthenticationFilter,
                        UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration configuration)
            throws Exception {
        return configuration.getAuthenticationManager();
    }
}
```

### 规则顺序很重要

`requestMatchers` 从上到下匹配，**第一个命中的生效**。

所以：

- `permitAll()` 的公开路径必须写在最前面。
- `anyRequest().authenticated()` 必须写在最后。
- `/api/admin/**` 要在具体的 `/api/users/**` 之前还是之后？它们不冲突，但把粗粒度规则放前面更清晰。

### 为什么 GET 和 POST 要分开写

同一个路径，不同 HTTP 方法可能需要不同权限：

- `GET /api/users` 需要 `user:list`
- `POST /api/users` 需要 `user:add`

如果只写 `.requestMatchers("/api/users/**").hasAuthority("user:list")`，那新增用户也会要求 `user:list`，权限模型就乱了。

---

## 8.6 `hasRole` vs `hasAuthority`

| 写法 | 实际匹配的权限字符串 |
| --- | --- |
| `hasRole("SUPER_ADMIN")` | `ROLE_SUPER_ADMIN` |
| `hasAuthority("ROLE_SUPER_ADMIN")` | `ROLE_SUPER_ADMIN` |
| `hasAuthority("user:list")` | `user:list`（**不会**补前缀） |
| `hasRole("ROLE_SUPER_ADMIN")` | `ROLE_ROLE_SUPER_ADMIN`（**错误**） |

本系列的约定：

- 角色编码存 `SUPER_ADMIN`，放进 authorities 时由 `LoginUser` 加 `ROLE_` 前缀。
- 配置里用 `hasRole("SUPER_ADMIN")`。
- 权限编码存 `user:list`，原样放进 authorities，配置里用 `hasAuthority("user:list")`。

混用前缀是 403 的头号原因。

## 8.8 为什么匿名用户被拒绝时是 401，不是 403

Spring Security 默认会放一个 `AnonymousAuthenticationFilter`。未登录请求经过它之后，`SecurityContext` 里会有一个 `anonymousUser`。

流程：

1. `AuthorizationFilter` 发现 `anonymousUser` 没有所需权限，抛 `AccessDeniedException`。
2. `ExceptionTranslationFilter` 捕获后判断：当前认证是不是匿名？
3. 是匿名 → 调用 `AuthenticationEntryPoint` → **401**。
4. 不是匿名（真实登录用户）→ 调用 `AccessDeniedHandler` → **403**。

所以：

- 没带 Token → 401
- 带了 viewer Token 访问管理员接口 → 403

这是框架的智能处理，不是 bug。

## 8.9 常见报错

### 1. 有角色却 403

排查：

```sql
SELECT r.code
FROM sys_role r
JOIN sys_user_role ur ON ur.role_id = r.id
WHERE ur.user_id = 1;
```

确认角色编码是 `SUPER_ADMIN`，不是 `ROLE_SUPER_ADMIN`。

然后确认 `LoginUser` 里加的是 `ROLE_` + code，配置里用 `hasRole("SUPER_ADMIN")`。

### 2. 公开接口还是 401

原因：请求头带了一个非法/过期 Token，过滤器解析失败，但请求本身是公开接口。

解决：公开接口不要带旧 Token；或者确认过滤器捕获异常后继续放行。

### 3. 403 返回 HTML 或空响应

原因：没有配置 `AccessDeniedHandler`。

解决：确认 `SecurityConfig` 里 `.accessDeniedHandler(accessDeniedHandler)`，并且 `RestAccessDeniedHandler` 是 `@Component`。

### 4. 所有接口都 403

原因：`anyRequest().authenticated()` 写在了具体规则前面，或者规则顺序错了。

解决：`anyRequest()` 必须最后；具体路径规则在前面。

### 5. `PUT /api/users/1/roles` 返回 403

原因：这个请求是 PUT，匹配的是 `user:update` 规则。如果当前用户没有 `user:update`，就会 403。

解决：确认角色权限里包含 `user:update`；第 10 章会专门讲分配角色。

### 6. `hasRole("ROLE_SUPER_ADMIN")` 永远 403

原因：`hasRole` 会自动补 `ROLE_`，变成 `ROLE_ROLE_SUPER_ADMIN`。

解决：写 `hasRole("SUPER_ADMIN")` 或 `hasAuthority("ROLE_SUPER_ADMIN")`，二选一，不要混。

## 8.10 本章小结

- 401 由 `AuthenticationEntryPoint` 处理，403 由 `AccessDeniedHandler` 处理。
- URL 规则从上到下匹配，第一个命中的生效。
- `hasRole` 自动补 `ROLE_`，`hasAuthority` 精确匹配。
- 未登录被拒绝时是 401，已登录但没权限是 403。
- 三个账号的权限矩阵已经可以验证。

<summary>参考答案</summary>
