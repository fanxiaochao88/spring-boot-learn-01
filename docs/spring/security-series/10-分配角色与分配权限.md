# 第 10 章 分配角色与分配权限

> 本章目标：通过接口给用户分配角色、给角色分配权限。
> 最重要的验证：**不重新登录**，旧 Token 立即反映新权限。

---

## 10.1 前置检查

第 09 章完成：

```bash
curl -o /dev/null -s -w "%{http_code}\n" \
  -X POST http://localhost:8080/api/users \
  -H "Authorization: Bearer $VIEWER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"check_user","password":"123456","status":1}'
```

预期 403（viewer 没有 `user:add`）。

---

## 10.2 要做的两件事

1. 给用户分配角色：`PUT /api/users/{id}/roles`，body `{"roleIds":[1,2]}`
2. 给角色分配权限：`PUT /api/roles/{id}/permissions`，body `{"permissionIds":[1,5,9]}`

两个操作都是“先删后插”：

```text
开启事务
  DELETE 该用户的所有角色
  逐条 INSERT 新角色
提交事务
```

为什么不用“对比差异再增删”？

- 对学习项目来说，“先删后插”最简单、最不容易漏。
- 数据量小，性能不是问题。
- 生产环境如果并发高，要加乐观锁或分布式锁，避免两个管理员同时改同一个用户。

### 10.3.3 修改 `UserServiceImpl`

`src/main/java/com/keywin/security/modules/user/service/impl/UserServiceImpl.java` **完整替换为**：

```java
package com.keywin.security.modules.user.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.keywin.security.common.api.PageResult;
import com.keywin.security.common.api.ResultCode;
import com.keywin.security.common.exception.BusinessException;
import com.keywin.security.modules.role.entity.SysRole;
import com.keywin.security.modules.role.mapper.SysRoleMapper;
import com.keywin.security.modules.role.mapper.SysUserRoleMapper;
import com.keywin.security.modules.user.dto.UserCreateDTO;
import com.keywin.security.modules.user.dto.UserUpdateDTO;
import com.keywin.security.modules.user.entity.SysUser;
import com.keywin.security.modules.user.mapper.SysUserMapper;
import com.keywin.security.modules.user.service.UserService;
import com.keywin.security.modules.user.vo.UserVO;
import lombok.RequiredArgsConstructor;
import org.springframework.beans.BeanUtils;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.util.StringUtils;

import java.util.List;

@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {

    private final SysUserMapper sysUserMapper;
    private final SysRoleMapper sysRoleMapper;
    private final SysUserRoleMapper sysUserRoleMapper;
    private final PasswordEncoder passwordEncoder;

    @Override
    public PageResult<UserVO> page(long page, long size, String keyword) {
        Page<SysUser> pageParam = new Page<>(page, size);
        LambdaQueryWrapper<SysUser> wrapper = new LambdaQueryWrapper<>();

        if (StringUtils.hasText(keyword)) {
            wrapper.and(w -> w.like(SysUser::getUsername, keyword)
                    .or()
                    .like(SysUser::getNickname, keyword));
        }
        wrapper.orderByAsc(SysUser::getId);

        Page<SysUser> result = sysUserMapper.selectPage(pageParam, wrapper);
        List<UserVO> records = result.getRecords().stream()
                .map(this::toVO)
                .toList();

        return new PageResult<>(result.getTotal(), result.getCurrent(), result.getSize(), records);
    }

    @Override
    public UserVO getById(Long id) {
        return toVO(getUserOrThrow(id));
    }

    @Override
    @Transactional
    public Long create(UserCreateDTO dto) {
        Long count = sysUserMapper.selectCount(
                new LambdaQueryWrapper<SysUser>().eq(SysUser::getUsername, dto.getUsername()));
        if (count > 0) {
            throw new BusinessException(ResultCode.CONFLICT, "用户名已存在");
        }

        SysUser user = new SysUser();
        user.setUsername(dto.getUsername());
        user.setPasswordHash(passwordEncoder.encode(dto.getPassword()));
        user.setNickname(dto.getNickname());
        user.setPhone(dto.getPhone());
        user.setEmail(dto.getEmail());
        user.setStatus(dto.getStatus() == null ? 1 : dto.getStatus());
        user.setTokenVersion(0);

        sysUserMapper.insert(user);
        return user.getId();
    }

    @Override
    @Transactional
    public void update(Long id, UserUpdateDTO dto) {
        SysUser user = getUserOrThrow(id);

        if (StringUtils.hasText(dto.getPassword())) {
            user.setPasswordHash(passwordEncoder.encode(dto.getPassword()));
            user.setTokenVersion(user.getTokenVersion() + 1);
        }
        if (dto.getNickname() != null) {
            user.setNickname(dto.getNickname());
        }
        if (dto.getPhone() != null) {
            user.setPhone(dto.getPhone());
        }
        if (dto.getEmail() != null) {
            user.setEmail(dto.getEmail());
        }
        if (dto.getStatus() != null) {
            user.setStatus(dto.getStatus());
        }

        sysUserMapper.updateById(user);
    }

    @Override
    @Transactional
    public void delete(Long id) {
        getUserOrThrow(id);
        sysUserMapper.deleteById(id);
    }

    @Override
    public List<Long> getRoleIds(Long userId) {
        getUserOrThrow(userId);
        return sysUserRoleMapper.selectRoleIdsByUserId(userId);
    }

    @Override
    @Transactional
    public void assignRoles(Long userId, List<Long> roleIds) {
        getUserOrThrow(userId);

        List<Long> distinctRoleIds = roleIds == null
                ? List.of()
                : roleIds.stream().distinct().toList();

        // 校验角色 ID 都存在
        if (!distinctRoleIds.isEmpty()) {
            Long count = sysRoleMapper.selectCount(
                    new LambdaQueryWrapper<SysRole>().in(SysRole::getId, distinctRoleIds));
            if (count.intValue() != distinctRoleIds.size()) {
                throw new BusinessException(ResultCode.BAD_REQUEST, "存在不合法的角色 ID");
            }
        }

        // 先删后插：整个方法在同一个事务里
        sysUserRoleMapper.deleteByUserId(userId);
        distinctRoleIds.forEach(roleId -> sysUserRoleMapper.insert(userId, roleId));
    }

    private SysUser getUserOrThrow(Long id) {
        SysUser user = sysUserMapper.selectById(id);
        if (user == null) {
            throw new BusinessException(ResultCode.NOT_FOUND, "用户不存在");
        }
        return user;
    }

    private UserVO toVO(SysUser user) {
        UserVO vo = new UserVO();
        BeanUtils.copyProperties(user, vo);
        return vo;
    }
}
```

## 10.5 验证：权限热更新（本章核心）

### 10.5.1 准备 Token

```bash
ADMIN_TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' \
  | python -c "import sys, json; print(json.load(sys.stdin)['data']['token'])")

VIEWER_TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"viewer","password":"viewer123"}' \
  | python -c "import sys, json; print(json.load(sys.stdin)['data']['token'])")
```

```bash
curl -s http://localhost:8080/api/users/3/roles \
```

```json

```

### 10.5.4 不重新登录，旧 viewer Token 立即有权限

**关键：不要重新登录，继续用第 10.5.1 步拿到的 `VIEWER_TOKEN`。**

```bash
curl -i -X POST http://localhost:8080/api/users \
  -H "Authorization: Bearer $VIEWER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"viewer_promoted","password":"123456","status":1}'
```

预期 200，创建成功。

为什么？

- JWT 里只有 `userId`、`username`、`tokenVersion`，没有权限。
- `JwtAuthenticationFilter` 每次请求都调用 `loadUserByUsername`，从数据库重新加载角色和权限。
- 所以角色一改，下一次请求立即生效。

```bash

  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
```

## 10.6 事务与并发说明

### 为什么用 `@Transactional`

`assignRoles` 里先 `deleteByUserId`，再循环 `insert`。如果插入到一半失败（比如某个 roleId 不存在、数据库异常），没有事务就会留下“角色被清空但新角色没插完”的脏数据。

`@Transactional` 保证：

- 全部成功 → 提交
- 任何一步失败 → 回滚，旧角色还在

### “先删后插”的并发风险

两个管理员同时给同一个用户分配角色：

```text
管理员 A：删除旧角色 -> 插入角色 [2]
管理员 B：删除旧角色 -> 插入角色 [3]
```

最终可能是 `[2,3]`，也可能是 `[3]`，取决于执行顺序。

学习阶段不用处理。生产环境可以考虑：

- 乐观锁（版本号）
- 分布式锁（Redis）
- 数据库唯一约束 + 幂等设计

### 空列表表示清空

`{"roleIds":[]}` 会删除该用户所有角色。

这是有意的：前端“取消所有勾选”时，需要能表达“清空”。

## 10.7 常见报错

### 1. 分配后权限没变化

原因：权限被放进了 JWT，或者过滤器没有每次从数据库加载。

解决：

- 确认 JWT 里只有 `userId`、`username`、`tokenVersion`。
- 确认 `JwtAuthenticationFilter` 每次请求都调用 `loadUserByUsername`。

### 2. 分配时报外键约束失败

原因：传了不存在的 roleId / permissionId。

解决：代码里已经先校验数量；如果仍然失败，检查 `sys_role` / `sys_permission` 里是否有这些 ID。

### 3. `@Transactional` 没生效

原因：

- 方法不是 public
- 同类内部调用（`this.assignRoles()`）
- 异常被 catch 掉了，没有抛出

解决：从 Controller 调用 Service 接口方法；异常让它抛出。

### 4. 403，提示权限不足

原因：当前用户没有 `user:update` 或 `role:update`。

解决：用 admin Token 操作；或者先给当前用户分配对应权限。

### 5. 传了重复的 roleId

代码里 `distinct()` 会去重，不会报错。

### 6. 传空数组报 400

检查 DTO 的 `@NotNull`：空数组不是 null，能通过校验；如果是 null，会 400。

## 10.8 本章小结

- `PUT /api/users/{id}/roles` 覆盖式分配用户角色。
- `PUT /api/roles/{id}/permissions` 覆盖式分配角色权限。
- 先删后插，方法加 `@Transactional`。
- 空列表表示清空。
- 权限每次从数据库加载，所以旧 Token 立即反映新权限。
- 并发场景需要额外锁，学习阶段先不处理。

### 自测题

1. 为什么“先删后插”需要事务？
2. 为什么改完角色后，不重新登录也能生效？
3. 如果把权限放进 JWT，第 10.5.4 步会发生什么？
4. 空数组和 null 分别会发生什么？

<details>
<summary>参考答案</summary>

1. 防止删除成功但插入失败，留下不完整的角色数据；事务保证要么全成功，要么全回滚。
2. 过滤器每次请求都从数据库加载角色和权限，不依赖 JWT 里的权限。
3. 旧 Token 里的权限不会变，viewer 仍然 403，必须重新登录。
4. 空数组会清空角色/权限；null 会被 `@NotNull` 拦下，返回 400。

</details>
